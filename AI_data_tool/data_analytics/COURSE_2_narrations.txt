=== Automated Explanation 307 ===
The automated explanation object determines the most important underlying factors that explain a particular variable. You must specify a response variable to explain.
The automated explanation object does several things. Once you provide it a response data item, it displays summary and characteristic information about the response factor, such as the range, and information about outliers. It also displays a bar chart, which shows the relative importance of the underlying factors in descending order of importance. Finally, it displays a relationship plot, representing the relationship between the response variable and a selected underlying factor. The type of plot depends on the variable type of both the underlying factor and the response variable.
The automated explanation object has three roles: Response, Time, and Underlying factors. When you assign a data item to the Response variable, most of the remaining data items are automatically added as underlying factors. However, aggregated measures, date and time values, and automatically computed values such as frequency, hierarchies, filter items, interaction effects, and spline effects are not added as underlying factors. SAS Visual Analytics also screens the remaining data items and rejects any that don't meet certain criteria, such as being identical to another variable, being a subset of the response data, having extremely high cardinality, or having a large number of missing values.
The relative importance bar chart displays all of the data items assigned to the Underlying factors roles, in descending order of importance to the Response data item. The most important factor is assigned a value of 1, and all the other scores are proportional to that. You can remove any individual underlying factor from the right-click context menu. A filter action is defined, so that clicking on a bar in the bar chart will update the relationship plot.
The type of relationship plot depends on the variable type of both the response variable and the selected underlying factor. If the both the underlying factor and the response variable are measures, then the relationship plot is either a scatter plot or a heat map. If the response variable is a measure and the underlying factor is a category, a bar chart is displayed. If the response is a measure and the underlying factor is a geography data item, then either a geo region or a geo coordinate map is displayed. If the response is a category and the underlying factor is a measure, then a histogram grouped by event level of interest is displayed. If both are categories, then a stacked bar chart grouped by event level of interest is displayed.
You can also optionally display a fourth object by turning on the High and low groups option in the Options pane. Doing so will display a High tab and a Low tab, where the three groups of the selected underlying factor resulting in both the highest and lowest average response values are displayed. For example, here the High tab displays the three groups of Retail Price values resulting in the highest values of Profit.

=== Automated Prediction 304 ===
The automated prediction object allows you to predict values of a selected response variable by specifying values for the underlying factors. The object runs several models and then chooses a champion model to use in the prediction.
The automated prediction object displays three components: the underlying values input form, the predicted response value, and a text description of the predicted value and model used.
The Automated Prediction object has two roles: Response and Underlying factors. The Response variable can be a category or measure data item that you want to predict. It cannot be a partition item or a calculated item that uses a parameter in the calculation. After a response variable is assigned, the other variables are assigned to the Underlying factors role. Aggregated measures, date and time values, calculated items, custom categories, derived items, and automatically computed values such as frequency, hierarchies, filter items, partition items, interaction effects, and spline effects are not added as underlying factors. Additional variables are rejected during the variable screening process, such as those with excessive missing values, high correlation with the response, or high cardinality.
Once you have specified a response variable to predict, the automated prediction object runs several models and chooses a champion model that best explains the response variable. The type of models tested depends on whether the response variable is a category or a measure. For a category response, the object compares: logistic regression (binary response only), gradient boosting, and decision tree. The champion model is based on the highest accuracy of 100 minus the misclassification rate. For a measure response, the candidate models that are run are: linear regression, gradient boosting, and decision tree. The champion model is based on the lowest average squared error (ASE). Additional information about the model selection is available by maximizing the automated prediction object.
Once a model has been selected, it will identify the most important underlying factors in the values input form. By default, it displays the most common or median values for all underlying factors and the resulting predicted response value. You can then enter or select new values using the form and see how the predicted response value changes. Each time you update an input value, the model automatically runs and displays an updated prediction.
There are a few things that you should keep in mind when you're using the automated prediction object. They are excluded from all report and page prompts, and you can't use them as the source or target of actions. Additionally, while SAS Visual Analytics will run several models each time you select new underlying values, you can't select a model yourself. For more control over the model selection process, you can instead use SAS Visual Statistics.

=== Bubble Plots 208 ===
Bubble plots are useful for displaying three dimensions of data for some group of category values. A bubble plot compares at least three measures by using markers (bubbles) of varying sizes in a scatter plot. The values of two measures determine the location of the bubble in the plot, and the value of the third measure determines the size of the bubble. A bubble's size is scaled relative to the minimum and maximum values of the size variable. The minimum and maximum values are displayed in the legend.
By default, bubble plots display non-aggregated data. This means that a bubble plot will attempt to display one bubble for every row in the data source. If you use a large table or use data items with high cardinality, a message appears that no data is displayed because too many values were returned from the query. You can assign a category to the Group role or create a filter to reduce the data. As a best practice, if you are using big data, assign a category to the Group role before assigning the measures to avoid this message.
Bubble plots can also be animated to show changes in data over time. When a data item is assigned to the Animation role, a player is added to the graph, which you can use to play and pause the animation, step through the date intervals, change the animation speed and loop the animation. In addition, options are available to format the animation date or time value that is displayed in the chart. For animated bubble plots, you want to focus on bubbles that act differently than others (for example, bubbles that are stationary while others are moving or bubbles that are moving in a different direction from the rest of the group).
Bubble plots require three measures: X axis (for the horizontal location), Y axis (for the vertical location) and size (for the bubble size). Additionally, bubble plots can contain groups, accept the color role, use lattice columns and rows, specify data tip values, display animation, and support the hidden data role. Options are available for changing the transparency of the bubbles and specifying the size range for the bubbles in the plot.

=== Correlation Matrices 254 ===
A correlation matrix can be used to evaluate the linear relationship between multiple measures. It displays the degree of correlation as a matrix of rectangular cells. Each cell represents the intersection of two measures, and the color of the cell indicates the degree of correlation between those measures. Lighter colors represent weaker correlation (near zero) while darker colors represent stronger correlation (near 1 or -1).
The correlation values are calculated by using Pearson's correlation coefficient. They are identified as weak (if the absolute value of the correlation is 0.3 or lower), moderate (if the absolute value of the correlation is greater than 0.3 and less than or equal to 0.6), or strong (if the absolute value of the correlation is greater than 0.6). Positive correlation values indicate that as one measure increases, so does the other, whereas negative correlation values indicate that as one measure increases, the other decreases.
You can see the calculated correlation value by hovering over a cell and viewing the data tip or by maximizing the chart and viewing the Details table.
If you would like to examine the relationship between two variables more closely, you can select the cell in the correlation matrix, right-click the cell and select New object from selection. This will enable you to create a heat map of the variables or a model (if your site has Visual Statistics available). Alternatively, you can select a whole column and create a new model using those variables.
Although two measures seem to have a weak relationship, this does not mean that they have no relationship. Remember that the correlation measures the linear relationship between measures. The actual relationship could be more complex or there could be insufficient data to show the relationship. Nonlinear relationships can best be displayed with either a scatter plot or a heat map.
Correlation matrices require measures. You can specify to show correlations within one set of measures or between two sets of measures.
If you display correlations within one set of measures (the default), all measures are compared to all other measures. In this case, the first variable you select will be displayed at the bottom left of the graph. If you have a target variable, it's recommended to select it first. If you display correlations between two sets of measures each set of measures is compared only to the other set of measures, not to other measures within that set. For example, in this correlation matrix, the measures on the Y axis (Product Quality and Product Price target) are only compared to the measures on the X axis (Product Sale, Product Cost of Sale, and Product Material Cost) and are not compared to each other.
Options are available for adding a border around each cell and rotating the axis labels so the entire measure name is displayed.

=== Fit Lines 238 ===
Fit lines can be added to scatter plots and heat maps of measures to plot the relationship between variables. When adding a fit line, you can select the type of relationship to plot: linear, quadratic, cubic, best fit, or PSpline.
To add a fit line, right-click the chart, select Fit line, and choose the type or use the Options pane to specify the type of fit line.
A linear relationship is plotted as a straight line that represents the relationship between the measures. For this method, correlation information is automatically added to the plot.
A quadratic relationship is plotted as a line with a single curve that represents the relationship between the measures. This method produces a line with the shape of a parabola, containing a single inflection point.
A cubic relationship is plotted as a line with two curves that represents the relationship between the measures. This method often produces a line with an S shape, containing two inflection points.
Best fit selects the most appropriate model (linear, quadratic, or cubic) for your data. This method uses backward variable selection to select the highest-order model that is significant. No penalty is assigned for complexity, so best fit often selects more complex models (like cubic and quadratic) over simpler models (like linear). Be cautious of overfitting. In most cases, the linear fit line is appropriate.
A P-spline relationship creates a penalized B-spline, which is a smoothing spline that closely fits the data. A spline is a function defined by piecewise polynomials. This method can display a complex line with many changes in its curvature.
Once a fit line has been added, you can view more information about the model by maximizing the object and viewing the details table. The Analysis tab displays information like the model type and description, the R-squared value, correlation information and the slope (for linear fit lines), the function of the fit line, the average x and y values, the standard deviation for the x and y values, and the number of observations.
For best fit, you can view this table to determine which model was chosen. Recall that best fit uses backward variable selection to choose the appropriate model. In this example, the cubic model was chosen, but viewing the function shows that the coefficients for the x-squared and x-cubed terms are very small. A linear fit line might be the best choice.
For PSpline, only the model type and description, the R-square value, and the error sum of squares are displayed.

=== Heat Maps 113 ===
Heat maps can be used to evaluate the relationship between two high-cardinality measures, between two categories, or between a category and a measure. A heat map displays the distribution of values for two data items by using a table with colored cells. Heat maps are especially useful to visualize trends between measures, to pinpoint possible outliers, and to identify nonlinear relationships.
Heat maps require Axis Items. You can assign two data items to display a single heat map or assign multiple data items to display a matrix of heat maps.
The matrix displays each possible paring of axis items that are assigned.
Additionally, heat maps accept the color role. Options are available for specifying the number of bins displayed, adding borders between cells, changing the transparency of the cells, and adding a fit line to the graph. The Bin count option only affects measures, and the Fit Line option is only available if at least two measures are assigned to the chart. For Fit lines, you can specify the type (None, Best fit, Linear, Quadratic, Cubic, or PSpline) and change the transparency of the line.

=== Numeric Series Plots 101 ===
Numeric series plots can be used to show a measure value at various intervals after some event. === Object Templates 443 ===
In Visual Analytics, all objects have default options set, which can be modified according to your report requirements. You might find yourself modifying the same options each time. For example, for bar charts, you might remove grid lines, change the direction to vertical, change the grouping style to stacked, and remove X axis labels. Instead of modifying the same options repeatedly, you can create an object template with your customizations. This ensures that your tables, graphs, and controls will have a similar appearance in multiple reports.
To work with object templates, follow these steps: (1) modify options to meet your requirements, (2) save the object to the Objects pane with your modifications, (3) give the object template a meaningful name, and (4) use the object template in your reports.
First, you modify options to customize the object as desired. You can modify general options (like object options, style options, and layout options), object-specific options, axis options (like axis label and tick values), graph options (like graph frame, reference lines, legend, and data options) or table options (like cells, cell visualizations, totals, and subtotals).
You can even save containers that include other objects, which can be useful for preserving the layout of objects and can help speed up development time. For containers, start by adding the container to the canvas. Then, add objects to the container and configure their layout. Next, modify the options for each object using the Options pane.
Next, save the object to the Objects pane. You can save the object by right-clicking the object and selecting Save to Objects pane, by selecting Save to Objects pane from the object toolbar, or by right-clicking the object in the Outline pane and selecting Save to Objects pane. For containers, use the Outline pane to save the container as an object template.
When you save the object, you can choose whether to save the object with or without data. If you include data, all data-related items (like role assignments, display rules, filters, ranks, and sorting) are saved with the object. This would be useful if you want to preserve these data assignments for use in another page or another report.
By default, object templates are available only to users who create them. However, application administrators have the option to publish the object template, making it available to all users. This enables users to create reports using objects with the same customizations.
After the object template has been saved, it's added to the Objects pane with a default name. Objects saved without data are added to the same group as the original object. For example, an object template for a bar chart will be added to the Graphs group. Objects saved with data are added to a new group, Objects with Data. You can edit the properties of the new object to give it a more meaningful name. Be aware that objects in the Objects pane are sorted alphabetically by default. You can name all object templates beginning with a space and a common prefix to more easily locate your customized objects. The space will ensure that your customized objects are displayed first in each group.
Users can change only the name of object templates they have created. Application administrators can change the name of any objects they have created and any published object templates.
Lastly, you will use the object template in your reports just like regular objects, by adding it to the canvas, assigning data, and adding any actions, filters, or ranks required for your scenario. When the object template is used in a report, it behaves just like any other object.
When creating object templates, there are some things to consider. You cannot save an object template for containers that contain custom graphs or model comparison objects. You cannot edit an object template. If you want to make changes, you can modify options for the object and create a new object template from those changes. The Duplicate as and Change object to options cannot be used to change objects to an object template. Deleting an object template will not delete any objects or reports that use the object template; it just deletes the object template from the Objects pane.
You can delete only object templates you have created. Application administrators, on the other hand, can delete their own object templates and any published object templates. If you do not want to see the object templates in your Objects pane, you can always hide them, just like any other object. It's a best practice to delete the object templates that are no longer in use.

=== Parallel Coordinates Plots 111 ===
Parallel coordinates plots are useful for analyzing multivariate data to understand interactions and correlations between data, for understanding features that contribute to specific outcomes, and for revealing clusters within the data. The plot displays data as lines moving through categories and binned measures. The thickness of each line indicates the relative number of observations in that bin.
You can select one or more bins to focus on the data of interest. In addition, you can right-click the object and select Reverse axes to reverse one or more of the ranges. This is useful for comparing variables that are inversely related.
You can also maximize the chart to see a details table that lists values of each variable for each polyline in the chart.
Parallel coordinates plots require at least two variables. These can be any combination of categories, dates, or measures. As a best practice, add your target variable first; this data item will be displayed in the first bin. Options are available for specifying the number of bins for each measure assigned to the plot and for limiting the maximum number of polylines generated by the algorithm.

=== Precision Container 227 ===
The precision container enables you to create a report with overlapping objects. You can control the placement, alignment, depth, and size of all objects within the container.
For each object in the container, the placement and size of the object can be controlled by specifying layout options: Left and Top determine the placement of the object from the top, left corner of the container and Width and Height determine the size of the object. These values are specified as percentages, not the pixel size, so they will adjust when the screen resolution changes. It's a best practice to use whole numbers for the layout options.
The alignment of the objects can be controlled by using the alignment guides that appear when you move objects within the container. You can also align objects by selecting two or more objects and using the Align icon from the report toolbar. This enables you to align the objects both horizontally (Align left, Align center, and Align right) and vertically (Align top, Align middle, and Align bottom).
The depth of the objects can be controlled by right-clicking the object and selecting Send to back or Send to front.
Because precision containers allow layering of objects, they are often used to add an image background to the report. Most objects are transparent, so the background image is visible. When adding a background image, be sure to adjust the text and fill colors of your charts so they appear with sufficient contrast and are easy to see. Be aware, that precision containers can cause problems when reports are viewed on different screen sizes. When you use them, it's recommended to set the report-level option Set fixed report size to specify a fixed size of the report. If you use this option, however, be sure to test thoroughly on all screen sizes.
You can modify the layout of the precision container by specifying the container type (flow, stacking, or precision).
When working with containers, it can often be difficult to move objects into and out of the container and to modify options for the container. You can use the Outline pane to organize objects in the container, to move objects into and out of a container, and to select the container on the page. In addition, you can use the drop-down control at the top of the Options pane to modify options for the container. You can also save containers that include objects as an object template. This is useful for preserving the layout of objects and can help speed up development time.

=== Prompt Container 154 ===
The prompt container can be used to organize multiple prompts and can be beneficial to mobile device users by enabling easier navigation. The prompt container enables you to group control objects together in a collapsible container, which will reduce the amount of space that control objects use in the report. The prompt container, unlike the other container types, can be used anywhere in the report: the report prompt area, the page prompt area, and the canvas. In addition, the prompt container enables you to add a list control to the report and page prompt areas when they are displayed above or below the canvas.
When the prompt container is used in the page or report prompt areas, you can define actions between controls. When the prompt container is used on the canvas, you can define actions between the control objects in a prompt container and other objects in the canvas. You cannot define an action to the prompt container itself. The prompt container is just a vessel for holding the controls.
You can modify the layout of the prompt container by specifying the direction of placement of controls in the container (vertical or horizontal), and by specifying the width and height of the container. To ensure compatibility with all screen sizes, you can specify that the prompt container's height or width should be extended if space is available. Conversely, you can indicate that the container height or width should shrink if there is not enough space. Other options are available for automatically applying values selected in the controls. If this option is not selected, selections are not applied to the report until you close the container to apply the changes. You may want to deselect this option to improve the speed of your report. This will apply all selections at once. In addition, options are available for specifying the label and styling of the button text, and for selecting a background color for the button and the button control bar.

=== Scatter Plots 149 ===
Scatter plots can be used to evaluate the relationship between two low-cardinality measures by displaying the values of both measures using markers. Each marker in the plot represents a single observation and the position of the marker indicates the value for each observation. Scatter plots are especially useful to visualize trends between measures, to pinpoint possible outliers, and to identify nonlinear relationships. Traditionally, the independent variable is displayed on the horizontal (x) axis and the dependent variable is displayed on the vertical (y) axis.
Scatter plots display detail data. This means that a scatter plot will attempt to display one marker for every row in the data source. If you use a large table or use data items with high cardinality, a message appears that no data is displayed because too many values were returned from the query. You can create a filter to reduce the data.
Scatter plots require Measures. You can assign two measures to display a single scatter plot or assign multiple measures to display a matrix of scatter plots.
The matrix displays each possible paring of measures that are assigned.
Additionally, scatter plots accept the color role, use lattice columns and rows, specify data tip values, display data labels, and support the hidden data role. Options are available for changing the transparency, shape, size, and fill of the markers. Additional options are available for displaying data labels, hiding data labels to minimize overlapping text and abbreviating numeric values. You can also add a fit line to the graph. === Scrolling Container 113 ===
The scrolling container enables you to create a report that functions like a web page. You can add more information, graphs can be larger, and the viewing experience can be improved for a mobile device or tablet. Each object fills the entire container area, and you must scroll to see other objects. This layout enables more clarification of objects because it enables you to add text to describe the object or text that includes additional information. It can, however, be tricky to design the report, as the sizing of objects will differ based on the screen resolution and the device. When using this container, it's a best practice to test the report thoroughly on all devices to ensure the report looks as intended.
You can modify the layout of the scrolling container by specifying the container type (flow, stacking, or precision). For the flow container type, you can also specify the direction of the flow (horizontal or vertical) and whether scrollbars should be avoided. For a scrolling container, Avoid scrollbars is not selected by default. When using a scrolling container, it's a best practice to specify the direction of the flow as vertical. This makes it easier for viewers to view the content on a computer.

=== Sharing Object Templates 339 ===
In some instances, you might need to share object templates with other SAS Viya environments. If you have separate environments for development, testing, and production, you might create the object templates in one environment and want to use those templates in another environment without having to re-create them. Alternatively, if you have opened a track with Tech Support, you might be asked to share the object templates for debugging purposes.
An application administrator can use the Export feature in SAS Environment Manager to export a JSON file that contains details about the object template, like the URI (uniform resource identifier), folder location, and details about the object template.
To share object templates, you need to follow three steps: (1) locate the object templates in SAS Content, (2) export the object template, and (3) import the object template in the new environment.
Object templates are stored on the SAS Infrastructure Data Server and are stored in the SAS Content/Products/SAS Visual Analytics/Resources folder.
Then, from SAS Environment Manager, you can use the Content page to navigate to the folder and export the object template, by right-clicking the resource and selecting Export or by selecting the object and clicking the Export button. Using this method, you can export each object template individually.
Alternatively, you can export all object templates by exporting the Resources folder. The Resources folder will include all object templates and data views in the current environment. Typically, if you are promoting content (by exporting from development to test to production), you will want to export all resources. This takes less time and is easier to maintain.
Instead, you can use the transfer plug-in to the Command Line Interface (CLI). The CLI enables you to interact directly with SAS Viya platform REST services and can be used to work with the platform programmatically. The CLI contains many plug-ins that can be used to manage authorization, users, services, licenses, and SAS Viya content (like folders, models, reports, or resources). The transfer plug-in has an export command that generates JSON files for SAS content.
To export an object template, use the transfer export command seen here.
The object-template-ID can be found on the Content page of SAS Environment Manager by navigating to the object template and viewing the URI (/reportTemplates/objects/object-template-ID). The json-file-name specifies the name of the JSON file that is created.
After the JSON file is created, you can use the Content page in SAS Environment Manager to import the object template (or all resources). Click the Import button at the top of the Content page or use the Import page in SAS Environment Manager. Because the folder structure is included in the JSON file, you can import from the top level of the Content page.
Importing content uses a wizard where you select the resources to import, map content and tables, preview the content items, and view the results. When the import is complete, your object templates will be available in the target environment.
Alternatively, you can use the transfer plug-in to the Command Line Interface (CLI). The transfer plug-in has an import command that imports JSON files to SAS Content. To import an object template, use the transfer import command seen here.
The json-file-id is provided when you upload the JSON file to the target environment.

=== Standard Container 113 ===
The standard container can be used to arrange objects horizontally or vertically without overlap. This container uses the default grid layout and resizes content to fit within the container with no scrollbars. You can nest several standard containers to quickly create columns, then modify the background color of each container to separate the columns. === Adding Scope to an Aggregated Measure 304 ===
Let's discuss another feature of aggregated measures: the ability to add scope. A scoped aggregated measure calculation is an expression defined for an intersection of categories. In other words, you can define different expressions for different intersections, or data crossings, allowing certain cells of a crosstab or other object to be calculated with a different expression. The scope will apply only when the defined categories for that intersection are included in the query. You must also define a base expression for the rest of the cells to use.
What do we mean by data crossing? A data crossing can be thought of as an intersection between two category variables in a crosstab. In this crosstab of Profit by Date and Order Type, we can think of each cell as the intersection between Date and Order Type, or Date/Order Type. Because there are only two category data items in this cross tab (Order Type as the column and Date as the row), there is only one intersection. Because there is only one intersection, any scoped measure would apply to all cells.
To use a scoped aggregated measure, we need to have multiple unique crossings to apply different expressions to. Let's look at an example. Imagine we have a crosstab displaying profit by both month and year, and by type of order, with a subtotal displaying the total yearly profit. Now, there are multiple intersections. As before, most of the cells represent the intersection between Date and Order Type. However, the final subtotal row represents the intersection between Order Year and Order Type. Because of this, we can create a scoped aggregated measure with one expression for the Date/Order Type intersection and another for the Order Year/Order Type intersection. For example, we can use one expression to return the monthly profit sums, and another to return the monthly average for the yearly subtotal row.
The first step is to open the expression editor by creating a new calculated data item. Then, you need to define a base expression that will be evaluated everywhere. In this case, the base expression is sum Profit, by group. This is what will be evaluated for every cell except the specific data crossings that you define.
Next, you need to add a new scope by clicking the Add button next to the Scope field. Then, you select the data crossing that you want to use to create the scope. In this case, we're specifying the intersection of Order Year and Order Type
Then, you can define a separate expression that will only be evaluated at the intersection of Order Year and Order Type. In this example, the expression is the sum by group of Profit divided by 12, which creates a monthly average.
When you add the scoped aggregated measure to the crosstab, you'll notice that all of the monthly rows are exactly the same. This is because they are being calculated using the base expression. However, notice that the Subtotal row is now different in the Profit (Scope) column. In the subtotal row, Order Year intersects with Order Type, and so the scoped expression is evaluated instead, returning the monthly average rather than the sum.

There are a few other considerations to be aware of when using the Suppress function, to ensure that any confidential information remains hidden. === Data Joins 458 ===
Data source joins enable you to combine two data sources. The join creates a temporary table that is executed every time that the report is opened.
Use data source joins to combine more than one data source in a single report object. You can also use them to create a multi-data source measure calculation. Do not use data source joins as a data-preparation tool to create a reporting data mart. It is recommended that any heavy lifting data processing be done before loading the data into CAS for reporting.
A data join and an append are two different data source actions. A data join combines two tables by matching data rows and adding columns. An append usually keeps the same column attributes and adds rows. Only the data join action is available in Visual Analytics.
Visual Analytics has four join types available. When defining the type of data join, the position of the tables determines the results. The industry standard is to call the two tables the left table or the right table. Recall from earlier that a join uses the matching criteria to look for common values and then adds the columns per the join specification. Let's walk through a simple example in which the number is representing our join match criterion. We can see that the left table contains the values 1 and 2, and the right table contains the values 1, 3, and 4. There is only one overlapping match value, 1.
Let's start with the left join. A left join selects all rows from the left table and only the matching rows in the right table. The result of this type of join has the same number of rows as the left table and includes both the matching and nonmatching rows from the left table.
Next, we have the right join. A right join selects all the rows from the right table and only the matching rows in the left table. The result of this type of join has the same number of rows as the right table and includes both the matching and nonmatching rows from the right table.
Next is the inner join. An inner join selects only the rows from the left table that match the rows from the right table, based on the join condition specified. The result of this type of join contains only matching rows.
And last is the full join. A full join selects all the rows from both the left and right tables. The result of this join contains both the matching and nonmatching rows from both tables.
Now I'd like to walk through a data join example in which we want to combine more than one data source in a single object. This is our target visualization. I'd like to build a bar chart that plots cylinders from the CARS_SPECS data source against the average of MSRP from the CARS_PRICING data source. I will use all the category data items for my matching criteria. Notice the data source CARS_SPECS on the left and CARS_PRICING on the right. For this example, I will perform a left join in which I want to keep all the rows with the cylinder data and keep only the rows that match with their MSRP values.
Now that I have a plan, let's execute. Using the Data source menu, select New data from join. You could select either New data from join option, but one gives you a list of available data sources in CAS versus the data sources that have been added to the report. Next, select the join type. The left data source is already selected because it's the data source that we started with, so select the right data source. Then use the add button to define the data item join mappings. Finally, at the bottom, select the data items that you want to include in the temporary result table.
Now when you view the available data sources in the report, you see the temporary table join result listed. You might notice that, if you included matching data items from both data sources, the data items from the right table have the table name added in parentheses. Now you can use the temporary table join result to build the desired bar chart. You can make any data item property edits that you want. In this case, I wanted the average MSRP, so I changed the aggregation from the default sum to average.
It's important when designing your reports to keep in mind that, with respect to performance, data joins are performed every time that the report is opened for every user. In regard to storage, data join results are temporary tables stored in the Casuser caslib that is visible only to the user who created the join, and the results are cleaned up automatically when no longer needed. Depending on the data sources, the temporary join results can be very large, and if many users access the report concurrently, then you could see performance issues. When considering joins, you can join only two separate tables. You cannot perform a self-join with the same data source. Also, only simple matching is available, and if date values are used in the matching criteria, make sure that the formats match. And most importantly, don't use data joins in the report to serve as your data preparation tool.

=== Periodic Functions 407 ===
Let's discuss another type of aggregated function available in SAS Visual Analytics. Periodic functions aggregate values over time. Periodic functions are evaluated over time intervals, allowing you to analyze how data changes over time. Therefore, to use the periodic functions, your data source must contain date or datetime data items.
There are five different periodic functions available in SAS Visual Analytics: CumulativePeriod, ParallelPeriod, Period, PeriodWithDate, and RelativePeriod. CumulativePeriod returns the aggregated value for a period of time and for all of the previous periods of time within a larger period. For example, it could return the year-to-date total of monthly values. ParallelPeriod returns the aggregated value for a period of time that is parallel to the current period. For example, it could return the value for the same week of the previous year. Period returns the aggregated value for a period of time -- for example, the value for the current month. PeriodWithDate returns the aggregated value for a specific, constant period of time. For example, you can use it to return the aggregated value for a month including a specified date. Finally, the RelativePeriod function returns the aggregated value for a period of time that is relative to the current period. For example, you could use it to calculate the value for the previous week of the same year.
Each period function aggregates data over an interval, which you must specify. There are six different intervals available: ByDay, ByWeek, ByQuarter, ByMonth, ByYear, and Inferred. The Inferred option means that the interval is evaluated based on its context in the object. For example, if your report contains a bar chart of sales by quarter, then the inferred interval is quarter. The level of granularity will depend on the granularity of your data source. If your data is at the week level, then you will not be able to use the ByDay interval.
In addition to the interval, each periodic function has a number of other parameters that you must specify. Let's consider the CumulativePeriod function. You must specify the aggregation, which can be either average, count, distinct count, max, min, or sum. You also need to specify the measure being aggregated, and the date data item used for the period calculation. The CumulativePeriod function takes two intervals: inner and outer. The inner interval is the interval for which the values are aggregated. The outer interval provides the context for the aggregation. For example, you can specify ByMonth as the inner interval and ByYear as the outer interval to aggregate the year-to-date values for each month. Next, you can also specify the offset, or how many outer intervals to offset from the current period. For example, if your inner interval is by month and your outer interval is by year, then -1 specifies the year-to-date monthly values for the previous year. The starting point is when each new outer period begins. For example, if your inner interval is by week and your outer interval is by year, then 3 specifies that each year begins in the third week. Finally, you must specify the scope, which indicates how much of each period is aggregated: either the full period, to a specified date in the outer interval, or until the current day's position in the outer interval.
Each periodic function also has one other option that we need to discuss: the filters option. Here, you must specify which filters should be applied before processing the aggregated measure. There are three different options: ApplyAllFilters, IgnoreAllTimeFrameFilters, and IgnoreInteractiveTimeFrameFilters. Selecting ApplyAllFilters means that all filters in the report will be applied before the aggregated measure is processed, where as IgnoreAllTimeFrameFilters means that all filters based on the date data item used in the period function will be ignored. Selecting IgnoreInteractiveTimeFrameFilters means that only filters selected by the viewer using prompts and actions will be ignored.

=== What is an Aggregated Data Source 144 ===
An aggregated data source in SAS Visual Analytics is a feature that creates a new temporary data source containing an aggregated subset of columns from the original data source. This new data source is generated when the report is opened and is available only for that specific report and user.
Aggregated data sources can also be used to get aggregate data analysis when working with detailed data.
Because an aggregated data source typically has both fewer columns and fewer rows than the original data source, using it in a report can help improve performance. Aggregated data sources can also be used to create nested aggregated measure calculations.
Consider an example.
The original data set might contain thousands and thousands of rows, with each row representing an individual event or record -- in this case, an order. You could create an aggregated data source based on this original data set by choosing a subset of columns. The rows in the original data source are aggregated by the categories that you select, and measures are aggregated using the aggregation type defined in the original data source.
In this example, if you create an aggregated data set using the Continent Name and Profit columns, or Customer Country and Profit columns, the Profit column will be aggregated based on the Sum aggregation type defined in the original data source, for each value of Continent Name or Customer Country. While the original data set may contain thousands or tens of thousands of rows since it was at the Order ID level, the aggregated data set will contain far fewer, since it will be aggregated to the distinct number of Continent Names or Customer Countries. The aggregated data set will then be added as a new data source in your Visual Analytics report.

=== Alert with Display Rules 227 ===
Alerts are notifications that are triggered by a set of data conditions defined by an expression display rule. To enable or disable an alert, you must be editing the report. The available recipients are registered SAS Viya users managed by an administrator. Subscribers of the alert will receive an email notification when the conditions are met based on the notification frequency. Alert messages also appear in the notifications area of the application bar.
The notification frequency is the cadence of how often users are notified. You can select between daily, hourly, or every minute and specify a corresponding interval. A notification will be sent the first time an alert is triggered, then will next be sent if the alert condition is met, at the specified interval.
The query frequency is how frequently the system checks to see whether the alert condition has been met. You can select between system default (which is every 10 mins), daily, hourly, or every minute at a corresponding interval. Regardless of how often the system checks to see if the alert condition is met, only the last state is checked at the notification frequency interval and if triggered, an alert will be sent.
Let's look at an example alert definition where the notification frequency is set to 7 days and the query frequency is set to once a day.
After the alert is defined, a notification is sent the first time the alert condition is triggered. For example, suppose that an alert created on Day 1 is triggered for the first time at 10:00 a.m. on Day 2. As a result, a notification is sent at 10 a.m. on Day 2.
Because the notification frequency is set to once every 7 days, the soonest that the next alert notification can be sent is on Day 9 at 10:00 a.m. This is true regardless of how often the alert criteria are met before that time.
At 10 a.m. on Day 9, SAS Visual Analytics determines whether the alert condition was triggered at the last system check. If it was, then a notification is sent. If it was not, then a notification is sent the next time the alert condition is triggered. For example, if the next alert is triggered at 8:00 a.m. on Day 11, then the notification is sent out. Based on this activity, the soonest that the next notification can be sent is 8:00 a.m. on Day 18.
If the notification frequency is modified, then the notification history is reset.

=== Types of Parameters 103 ===
A parameter is a variable whose value can be changed and that can be referenced by other objects. Parameters add interactivity to a report by enabling viewers to see what they want, when they want to see it, without having to ask a report designer to change the report for them. SAS Visual Analytics supports three different kinds of parameters: numeric, character, and date/datetime.
Parameters can help make your reports more dynamic by giving report viewers added control over their view of the report. They can be used in a variety of places in a report, including calculations, filters, text objects, ranks, display rules, or URL links.
To use parameters effectively, you need to follow three simple steps: create the parameter, populate the parameter, and apply the parameter. First, you'll need to determine the type of parameter that is required for your scenario: character, numeric, or date.
The easiest way to determine the parameter type is to think about what exactly you want report viewers to enter.

=== Using Character Parameters 306 ===
On the other hand, if you want the report viewer to choose a category or enter an alphanumeric string (for example, to choose a sales region and update the compensation numbers with bonus plan for that region), then you need to create a character parameter.
Character parameters can be created in the same three ways: using the New data item button, from within the Expression Editor, and by right-clicking on a data item.
Regardless of which option you select, in the New Parameter window, choose Character as the Type value. Unlike the numeric parameter, where you can also set minimum and maximum values, the only additional property you can modify is the Default value, which sets a starting value for the parameter. The Multiple values check box enables the parameter to accept more than one value.
It can only be used with a list control, and only used in the In, NotIn, and IsSet operators in filters and calculated expression.
Just like with numeric parameters, you populate the parameter by adding a control object to allow the report viewer to modify the parameter value.
The available control objects for character parameters are: text input, list, drop-down list, and button bar.
Note that the list control object can be used with a multiple-value character parameter.
Once you have selected the desired control object and dragged it to the canvas, you can select the parameter in the Actions pane. Character parameters can be used in calculated items and aggregated measures, anywhere that a character value makes sense. They can also be used in detail filters, aggregate filters, and data source filters, anywhere a character value makes sense. When a parameter is used in a data source filter, the filter will not apply to the control object associated with the parameter. Parameter values can also be specified in URLs when sharing a report link, and they can be displayed in text objects.

=== Using Date Parameters 313 ===
The third type of parameters is date parameters. You should choose a date parameter if you want your user to enter or to select a date or datetime. For example, you would use a date parameter to allow a user to select a date and then view the previous thirty days of profit from that selected date.

The available control objects for date and datetime parameters are: text input, slider, drop-down list, and button bar.

Like with other types of parameters, the final step is to apply them by using them in your report. Date and datetime parameters can be used in calculated items and aggregated measures, anywhere that a date makes sense. Date parameters can be used in detail filters, aggregated filters, and data source filters anywhere it makes sense to have a date value. === Using Expression-Based Parameters 318 ===
So far, all the parameters that we have discussed allow the report user to update the value of the parameter using a control object. However, there is another option. Expression-based parameters allow you to specify an expression to set the value of a parameter.
Expression-based parameters can be used with numeric, date values or character values. For example, you can use expression-based parameters to calculate the average profit per sale across an entire data set, and then use that parameter in other calculations to determine the difference from the average across regions and products, without the parameter being affected by filters or actions.
The process of creating an expression-based parameter is the same. You can create a parameter using the New data item button, from within the Expression Editor, and by right-clicking on a data item.
However, unlike the previous examples that we have discussed, you can also populate the parameter with an expression instead of with a control. To do this, rather than leaving the Default Value field blank or simply entering a static value, you can instead click Edit as expression to open an expression editor that defines the value of the parameter. For example, you can use an expression-based parameter to store the average per-order profit across an entire data set. The Expression Editor allows you to define the parameter's value using operators, a wide range of numeric, date-time and character functions, data items, other parameters, and filters and ranks for the expression. Once the parameter has been defined, its current value can be displayed by hovering over it in the Data pane.
Expression-based parameters can be used anywhere a regular parameter can be used. Because they are not affected by filters or actions in the report and are based on the entire data source, their value will remain constant no matter which filters or actions the user interacts with.
Although expression-based parameters can be used anywhere a regular numeric or date parameter can be used, they are particularly powerful for use in scenarios where you need to calculate the percent of a total, benchmark target values, or set the initial values of control objects.
For example, an expression-based parameter could be used in a calculated data item to calculate the difference between an individual order's profit and the total average profit per order. Because the parameter is defined using an expression, its value will update as new data is added, updating the value of the calculated item.
Then, that new calculated item can be used in visualizations as a benchmark value to compare with an individual region. In this example, the user can select a region to compare with the global average using a control, and the control is linked to the bar chart by a filter action. However, because the expression-based parameter referenced in the calculated item is based on the whole data source and happens outside the context of this particular visualization, its value is not impacted by the control.
Consider another example. By using date functions, you can create an expression-based parameter that returns the current date and a second one that returns 180 days before the current day. You could then use these parameters in a slider control to set the initial minimum and maximum values in a slider, to ensure that the initial selection is always the past 180 days, no matter when the report is opened.

=== Modifying Threshold and Data Limit Options 357 ===
A threshold and data limit is a number that limits the amount of data that can be visually displayed. Depending on the object, this number can represent detailed data rows, such as the scatter plot, or aggregated rows, such as the list table object. This number is controlled by the maxRowsLookup property. This option can be set at two different levels, either at a single use object level override or at the environment level which means that for every user that uses that report object, the new threshold number will be used.
The missing values option determines if missing values are included in the distinct count calculation. By default, missing values are included. This is controlled by the ignoreMissingValuesInDistinctCount property. This can only be changed at the environment level. This means every user, and every Visual Analytics report will calculate the Distinct Count the same.
A client-side threshold is the amount of data that CAS will send in the response to the client--in this case, Visual Analytics.
When you create an object in Visual Analytics, the client will send a request to CAS. CAS, similar to a data warehouse, contains all the data. The analytic engines summarize the data based on the object, the roles assigned, and any filters or ranks applied. After summarization is complete, the analytic engines limit the number of aggregated rows based on the object's client-side threshold and sends the aggregated result back to the client.
Let's consider an example. Suppose you would like to display a list of all your customers in a table. You have 68,300 customers, but the default client-side threshold for list tables is 40,000 rows. This means that the list table will display only 40,000 rows. If a total is included, this row counts as one of the 40,000.
To see all customers, you can modify the Override system data limit option to 70,000. In this case, all customers will be displayed in the list table.
Notice that even when the list table truncates the rows due to the client-side threshold, the totals are still accurate and based on all the data.
In most cases, it is better to only change the data limit for a specific object in a specific report. As a report author, you can override the system data limit using the Options pane of an object. While this modification can impact the performance of the report and the CAS server, the impact will be contained to this one object for this one report. You don't need administrative rights to change this value, having the right to edit the report is enough.
To edit environment level properties, you must be an administrator and have access to SAS Environment Manager. These properties are under the Configuration pane and on the definitions tab you can search for the sas.reportdata.properties.
There an administrator can edit the configuration properties for an existing object or create a new configuration if one is not listed for the object by default. The threshold values are controlled by the maxRowsLookup property. Modifying these configuration properties will impact all instances of the object in the environment and can directly impact performance. Before making changes, ensure that the changes are necessary and that they will not adversely impact your environment.
Similar to the environment level threshold data configuration, the property that controls whether or not to count missing values in the Distinct Count calculation needs to be done by an administrator in SAS Environment Manager.
On the Configuration pane, use the definitions tab and search for sas.reportdata.properties. Then search for the ignoreMissingValuesInCountDistinct property. This property is a toggle, by default the missing values are included in the calculation so only toggle it on if you want to ignore missing values. Remember, this is an environment level option and applies to all users for all Distinct Count calculations.

=== Viewer Capabilities 327 ===
The Viewer Capabilities option, in the Options pane at the report level, controls the customizations that can be made by the report viewer. This option can be set to simple edits, comprehensive edits (the default), or data edits. Each of the levels are additive, meaning that comprehensive edits include capabilities for simple edits and data edits include capabilities for comprehensive edits and simple edits.
NOTE: The Viewer Capabilities option was introduced in SAS Visual Analytics 8.4.
The simple edits level enables report viewers to make small changes to the report that do not change the original intent of the report. For example, report viewers can change how the data is sorted in an object and specify simple options for the object (like showing data labels and legends and modifying the grouping style).
Comprehensive edits, the default level, enables report viewers to make changes to the report that might alter the original intent of the report. For example, report viewers can change object types. This level also includes all the capabilities provided with simple edits.
The data edits level enables report viewers to change the data for objects in the report. This option setting gives report viewers almost full control of the report. For example, report viewers can change data assignments, filters, and ranks for objects. This level also includes all the capabilities provided with comprehensive edits.
When setting the Viewer Capabilities option, there are some things to consider.
Recall that this option is assigned at the report level, meaning that these capabilities cannot be assigned by user or by group. If you want to apply different levels to the same report for various users or groups, you must save the report for each user or group and then grant access as appropriate. You can choose to identify groups of terms being used as a noun, such as SAS Institute. Note that these terms might also appear on their own.

To discover the topics from the parsed terms, a matrix with the frequencies of each term in each document is created. These frequencies can be weighted. Weights affect both topic creation and importance of terms within a topic. The idea behind weighting terms is to avoid more frequent terms from obscuring less frequent but more informative terms. According to Zipf's law, the most common word occurs approximately twice as often as the next common one.
The weight applied is the product of the cell weight and term weight. The cell weight is calculated for each document. The term weight is applied based on the distribution of the term across the whole document collection.
You can choose to not apply a cell weight. The other option is to use logarithmic cell weight, which reduces the importance of high-frequency terms in each document. A rule of thumb is to use a cell weight of None for short documents without too many repetitive words, where Zipf's law plays a smaller role. For term weight, you can choose between weighting terms by their frequency in the document collection, or weighting by entropy. Entropy can give a higher weight to more uncommon terms if they help distinguish between documents. It is recommended to use a stop list when applying term weight based on entropy. Note these are just rules of thumb. Experiment with different weights and select those that produce the best results for your document collection.

=== Decision Tree 735 ===
A decision tree is an explainable and powerful machine learning algorithm that can be used for both classification and regression tasks and uses the C4.5 algorithm, an iterative dichotomizer. Classification refers to predicting a group to which an observation belongs, such as flower species. Regression refers to predicting a continuous numerical value, such as housing price.
By learning from the data, a decision tree iteratively creates a set of decision rules to accurately predict the response variable. The resulting decision rules can be plotted in the form of an inverted tree. Starting from the root at the top, each branch represents an IF-THEN decision rule, and each node represents an outcome. The terminal nodes of the tree are called leaves.
Using criteria such as entropy and information gain, the decision tree automatically selects the most relevant predictor variables influencing the response variable and the optimal splitting points to determine each decision rule.
A base decision tree is included with a SAS Visual Analytics license. In this chapter, base decision tree functionality is marked as such. With a SAS Visual Statistics license, you have access to an advanced decision tree object, where you can see the importance of each predictor variable in the model and various assessment plots to evaluate the model performance.
Statistics starts with data. Think of the data as being generated by what you are studying, these input variables called predictors go in one side, and on the other side, the response variables come out. The response variable is often also called the target. Decision trees are considered white box models because their structure is easily visualized, the decision-making process is transparent and easily understandable. The Decision Tree will determine the relationship of the input variables to response variables.
There are two goals in analyzing the data: explanation and prediction.
Explanation (or explanatory analysis) is the extraction of some information about how nature associates the response variables to the input variables.
Prediction (or predictive modeling) refers to predicting the responses for new data.
The base functionality provided by the Visual Analytics license only supports explanation.
In this chapter, you will build a decision tree to classify Iris flowers. There are three species of Iris Flowers: Setosa, Versicolor and Virginica. They can be characterized by the width and lengths of their petals and sepals.
The first step to creating a decision tree is selecting a response variable. This is the outcome variable you want to predict or explain. It can be a measure or a category. For categorical response variables, you need to select an event level. This is one of the category values that you want to predict. This is necessary for creating the correct assessment statistics.
For example, we may want to predict which flowers are Setosa.
Next, we need to select predictors. These are variables that can help predict or explain the response variable. Decision trees automatically select the most relevant predictors. Note that, like other machine learning algorithms, decision trees' predictive power decreases with a higher number of predictors.
The response and predictor data items make up our input data.
Next, the model then trains on the data, learning the data's features to create a set of decision rules and build the tree.
You may be interested in what distinguishes Iris species out of curiosity, or to apply this knowledge offline. The explanation, how is the response variable related to the predictors would pose the question: how does petal length and width determine the flower type?
You can use the mouse wheel or pinch out with two fingers on your laptop trackpad to zoom in on the decision tree and explore how the predictor variables affect the response variable. By zooming in on a node, you can see how many observations from each response level fall into that node.
Each branch of the tree displays the name of the predictor for the branch at the top of the split. The thickness of the branch indicates the number of observations that are associated with each node. The predictor values for each node are displayed above the node.
The bar chart in each node displays the values of the response data item that are selected by the splits in the tree.
If the response is continuous data then the response is binned. In that case you will see a histogram instead of bar chart and standard deviations on each node.
You can right-click on the decision tree to change the displayed statistic to percent. You can also derive the leaf ID as a new data item.
You can also use your decision tree model for prediction. In this case, you will score new data using the model. For example, you could use this model to predict the species of new Iris flowers.
For scoring, the model is first translated into another format called score code. In the SAS Viya environment, score code is a SAS program that you can easily run on a scoring data set. SAS Viya creates two types of SAS language score code: either DATA step code or analytic store (ASTORE) code. Then, the model is applied to the scoring data set to obtain predicted outcomes, as well as probabilities for the target event level, or all event levels. The resulting dataset is generally known as scored data. Based on the predictions from the model, the enterprise makes business decisions and acts.
With a categorical response variable, the model produces a probability that the event level is reached. For example, the model might state there is a 50% probability that a given flower is Setosa. Would you classify this as Setosa or not? The choice you make will influence the number of false positives and false negatives.
In the decision tree options, you can set a prediction cutoff, which is the probability from which we consider that the outcome occurs.
Let us consider an example where there are only two outcome levels: Setosa and Virginica. The event level we chose to model is Virginica.
In the training data, 0% of flowers with a petal width of less than 6 millimeters are Virginica. Of flowers with a petal width of more than 6 millimeters, 98% are Virginica. Let us score some data using this model.
The first flower in the scoring data has a petal width of 2 millimeters. It falls under the leaf on the left, where there is a 0% probability that it is Virginica. The second flower has a petal width of 18. It falls under the right leaf, where 98% of flowers were Virginica. As this is above the prediction cutoff of 0%, this flower is classified as Virginica.
Imagine you are a teacher that wants to assess your students' understanding of algebra. You will give them questions to practice. Typically, the questions in the exam will be different. Otherwise, they might memorize the solutions to the practice questions, but you will not know how well they answer new questions. In the machine learning world, this is known as overfitting. To get an honest assessment of a model's performance, the data is split into a training and validation partition. The training partition (usually 70% or 80% of the input data) is used to build the model. The model is then run on the validation dataset. The model's predictions in the validation dataset are compared to the observed outcomes to get an honest assessment of the model's performance.

=== Forecasting 435 ===
When forecasting is mentioned, most people think of sales forecasts or forecasts about the state of the economy. However, forecasts can be useful for any industry. A forecasting object uses the statistical trends in your data source to predict future data values. Forecasting can be useful in any industry. Visual Analytics can evaluate additional measures to determine if they contribute to the forecast as an underlying factor. If a forecast is determined to have a contributing underlying factor, Visual Analytics provides What-If Analysis including What-If Scenario Analysis and What-If Goal-Seeking.
The forecast displays a line with predicted values and a colored band that represents the confidence interval. For example, a 95% confidence interval is the data range where the forecasting model is 95% confident what the future values will be.
Historical, or actual, values for the forecast model are displayed as markers only, without a line. Historical predicted values (hindcast) are displayed as part of the forecast line. Depending on the forecasting model that is selected, the historical prediction line might not begin at the start of the X axis.

The data can contain multiple rows for each date. In that case, the forecasted measure is aggregated for each date before forecasting is performed.
If your data contains multiple measures and you think some of those additional measures might contribute to the forecast, you can add them as possible underlying factors.
Visual Analytics automatically tests several forecasting models against your data ( ARIMA, damped-trend exponential smoothing, linear exponential smoothing, seasonal exponential smoothing, simple exponential smoothing, Winters method (additive), and Winters method (multiplicative)) and selects the best mode. The selected model can be viewed when in maximize mode on one of the results tabs.
SAS Visual Statistics and SAS Visual Data Mining and Machine Learning give you the added ability to create your own models instead of relying on the model that is automatically selected for forecasting. SAS Visual Forecasting, on the other hand, gives you the power to produce large-scale time series analyses and hierarchical forecasts.
Visual Analytics accounts for cyclical patterns by using standard intervals of time, such as 60 minutes in one hour, 24 hours in one day, and 12 months in one year. If your data uses nonstandard intervals, such as 48 thirty minute cycles in one day, then cyclical patterns are not considered in the forecast.
The forecast object offers options for the confidence interval. By default, the interval is set to 95% confidence, but this is customizable. You can also define the forecast horizon. The default is to project out 6 periods. The periods are dependent on the date data interval.
There is also an option for the time series binning interval. This specifies the interval between datetime values in the plot. The automatic option allows Visual Analytics to determine the best interval for the plot. The use format option plots all of the datetime values as rendered by the data format.

If you select automatic, then the measure layout is determined automatically depending on the format and data range of the measure values.
Forecasts are very useful in planning for the future. For example, you can use a forecast to predict the number of storms for the next six years based on historical storm occurrence. You can also use a forecast to predict the number of injuries from motor vehicle accidents for a specific city.
In addition, forecasts can be used to determine production of electricity so that staffing and transport planning can be made according to spikes. Forecasts can also be used to predict future performance, either in terms of sales or the volume of stocks sold.

=== Network Analysis 315 ===
Sometimes it seems everything is connected, events, relationships between people and places, data via transactions, even logistics. With advances in technology, it is now easier than ever to collect data about these connections and use that data to visualize a linked relationship. Network diagrams are a great way to look at this information.
One way to view the relationship between data is using a network analysis object. A network analysis object displays relationships by using a series of linked nodes that can have two structure types. The network analysis object also automatically calculates network metrics that can be used as either the size or color data roles. If you have geographic data items, you can also select to view the network analysis on a map background.
The network analysis object's data roles are controlled by the network structure general option. There are two types of network data structures that are supported, ungrouped and hierarchical.
An ungrouped network diagram creates a series of linked nodes from a source to a target. The nodes and links represent connections between those data values.
A hierarchical network diagram uses a defined arrangement of category data items which displays a parent-child relationship. It can show disconnected clusters of nodes depending on the underlying values.
The network analysis object also has a link type general option that can show either a directed or undirected connection.
A directed link type is a one-way connection. This link type affects the calculation of the network metrics.
An undirected link type is bidirectional and also affects the calculation of the network metrics.
Another important network analysis general option is the additional levels slider. This applies to hierarchical networks only and specifies the number of levels that are displayed beneath the current level of hierarchy.
The options pane is where you can really customize the network analytics object. In the network display option group, you can choose to abbreviate numeric values, add data labels, turn on link arrows, turn on detailed link attributes, and select a link curvature percentage.
To further customize the network analysis object, you can choose the node size percentage.
For the node selection group, you must have identified a source node from the diagram and then you have the ability to select the number of successors to display.
If your network structure data items are geographic, then you can choose to use a map background.
The network analysis object automatically calculates network metrics that can be used to further enhance your diagram. These automatically generated measures can only be used in either the size or color data roles.
The betweenness Centrality indicates how often a given node is part of the shortest path between nodes.
The closeness centrality indicates how close a node is to all of its connected nodes.
The reach centrality indicates how many links away the farthest connected link is.
The color data role supports two additional network metrics that are automatically created.
The community identifies local groups of nodes.
And the disconnected network ID identifies each group of connected nodes.

=== Path Analysis 345 ===
For some types of analysis, you might be interested in flows of data. This could be steps in a process, flows through different loyalty levels, flows through pages in a website, or flows through product packages. Often, you want to see which path leads to some goal, like completion or the purchase of a product.
The path analysis object displays flows of data. This type of diagram is also called a Sankey diagram. When the object is maximized, there is a natural language explanation on the path analysis summary tab, and there are several link and path boundary options available for customization.
Visualizing the flow of data from one state to another was first done in 1898 to show the energy efficiency of a steam engine. The diagram showed the flow starting from the boiler through to the steam pipes and then to the valves, cylinders, and pistons that propel the train. The width of the arrows through the diagram is proportional to the flow rate of the energy.
Modern application of the Sankey diagram takes us to the path analysis object. This diagram also displays the flow of data from one event to another as a series of paths and is not limited to any type of state change. Each event in the data is called a node. The width of the path link represents either frequency or you can assign a weight measure. Linked nodes represent consecutive events. This example shows customer visits to a website and what pages were clicked in what order and if any products were purchased.
Use the maximize button to view the path analysis details. There are two tabs, path information which shows the data that makes up the diagram and the path analysis summary tab. This contains a Visual Analytics-generated natural language explanation of the path analysis results.
Links can be colored to show each path in a different color, to show each event in a different color, or to indicate drop-offs (where one path ended, and other paths continued).
Coloring links by path, displays each path as a separate group with a distinct color. It is useful if you have a small number of paths and you would like to follow each separately.
Coloring links by event, colors each link according to the event that it represents. This makes it easier to visually compare the same event throughout the diagram.
Coloring links by drop-off, colors the links in the diagram based on whether they are drop-off links. This makes it easier to identify where paths frequently end.
Using the Options pane, you can customize the appearance of the path analysis object. In the previous slide, we saw how link color specifies the method that is used to group and color the paths in the diagram. The link width option specifies whether the width of a link in the path represents the path frequency or the aggregated value of the weight measure. The minimum and maximum path length specifies the length a path is displayed. The minimum and maximum frequency specifies the path frequency to be displayed. The path ranking direction specifies whether the ranking selects the top or bottom value. The path ranking count specifies the count for the path ranking. By default, the ranking selects the top or bottom 200 paths. When selected, the compress option combines repeated, consecutive events in each path into a single event.
You can also choose a horizontal or vertical layout. If you select to use abbreviated numeric values you can also select the scale: automatic, thousands, millions, etc. and the number of digits of precision. You can also select to enable node labels which displays the event names, link labels which displays the width value for each link, nodes which displays the link width values, and outline which displays a box around each node.

=== Text Topics 738 ===
When thinking about analyzing data, you usually think of structured tables in which data is organized into rows and columns. With text analytics, however, it is possible to analyze unstructured columns of text as well. The main use of text topics is to provide a high-level summary of "what people are talking about". This could be free-form data like text in comment fields, customer complaints, movie reviews, job descriptions, book summaries, or the contents of health records.
A text topics object analyzes unstructured data that is referred to as the document collection. The data source must contain a unique row identifier that needs to be defined before assigning roles to the text topics object. There is an option to perform sentiment analysis and Visual Analytics supports over thirty languages for text topics. The available languages will be dependent on your license and installation.
There are some terms you need to familiarize yourself with before moving on. The unique row identifier is a data item that has a unique value for every observation. SAS typically detects and assigns such a column automatically. If there are multiple unique row identifiers, you have to select which one to use for the text topics object. If there are no unique row identifiers in the data source, ask the person who created it to create one, perhaps by concatenating multiple data items. The unique row identifier is labeled with a key icon in the Data pane.
The document collection is the data item with the unstructured text you want to analyze. Each observation in the document collection is called a document.
The first step in text analytics is to parse the unstructured text and retrieve terms. Terms are words or phrases. SAS uses natural language processing to identify and distinguish words used as different parts of speech, such as train (as a verb) and train (as a noun). At the same time, SAS considers different forms of a word, such as run and running, as the same term. SAS can also identify entities and groups of terms used as a noun. These options can be switched off if you wish and are discussed further later.
Once SAS has parsed the text and extracted the terms, the extracted terms are compared to the stop list. Extracted terms are removed if they are on the stop list. The words on the stop list are usually commonly used terms that likely add no meaning. This includes, for example, conjunctions and personal pronouns. Thus, the stop list allows only meaningful terms to be analyzed by text topics. Each language has its own stop list. The stop list is supplied by SAS. Using a stop list is optional but recommended.
Next, SAS can finally derive topics, which are terms that often appear in the same documents. For example, the drop, risk, supplier, dissatisfy topic is found in documents where the terms drop, risk, supplier and dissatisfy, as well as other terms that are not displayed, are employed. A plus prefix in front of a term indicates that multiple forms of the term are included in the topic. For example, drop includes dropping and dropped. We can use this topic to identify documents where the order note mentions that the customers are dissatisfied and might drop us. To find topics, SAS creates a large matrix with possibly weighted frequencies of each term in each document. The resultant matrix goes through Singular Value Decomposition for dimensionality reduction. You can request to extract the top 2-25 topics.
Optionally, SAS can calculate the sentiment in each document. This functionality is optional but set to off by default as it is calculation heavy. Words are classified into negative, neutral, and positive sentiment. Negative words contribute a score of 0, neutral words contribute a score of 0.5, and positive words contribute a score of 1 to the average calculation for the document sentiment score. The number of documents with positive, neutral and negative sentiment are displayed for each topic.
The text topics results feature a bar chart visualizing the number of documents each topic appears in. If sentiment analysis is enabled, the bars are grouped by sentiment. On the right, you see a word cloud of terms sized by the number of documents they appear in. At the bottom, you see a list a of documents and the average sentiment in the document, if enabled. Any data items selected in the Document details role are displayed next to the documents. You can right-click or double-click on a document to view the full document. With a right-click, you can also select multiple documents and create a list table from them. When you select a topic in the topics bar chart, the terms word cloud and the documents table are filtered by that topic. Note that a document is only displayed in the documents table if it contains at least one of the most significant terms in the selected topic. Furthermore, the documents table displays the relevance of the selected topic for each displayed document.
After you have completed text analytics, you can derive data items to further analyze the topics that are generated. Derived data items can be created from topics and relevance.
For derived relevance, the value represents the relevance of the topic in that document.
For derived topics, the value is either 1 (if the topic is included in the document) or 0 (if the topic is not included in the document). You can use these derived items as a filter or with other data items for deeper insights.
Select the derived items you want created. The selected derived items are then available from the Data pane and can be used in a variety of objects for further analysis.
In this first example, we have added both the derived topic category and the derived relevance measure to a List table object. In this object it is easy to see which documents contain the topic because you will see the number one and a larger relevance for those observations. The relevance measure can be higher either because the documents uses more terms from the topic or because it uses terms that have a higher weight in that topic.
In a bar chart example, the derived topic category is used as the group role. Here it is easy to see that only the North American continent contains documents with the topic. You can then investigate deeper into this data.
The last example is using a heatmap object. This object uses the derived relevance measure, and we can see that the higher order totals show a low relevance to the complaints. This is a positive thing to see that, at least in this case, those higher order customers are not talking about dropping the supplier.
The text topics model can be converted into ASTORE score code. To do this, right-click anywhere in the text topics object and select Generate ASTORE code. This code can then be applied to a new document collection to determine topics and topic relevance in each document.
When you maximize the text topics object, you see three tabs. If you click on topics, you see the data behind the topics bar chart, including the total amount of documents, and the amount of negative, neutral and positive documents per topic. Note that the topic selected is also highlighted in the bar chart above. The terms tab displays the terms within the selected topic, including the weight of the term within topic. If no topic is selected, top terms by document count are shown. Each term's part of speech is displayed if the corresponding role identification option is turned on. Lastly, the text topics summary tab gives a natural language explanation of the results.

=== Underlying Factors and What-If Analysis 312 ===
When you create a forecast in Visual Analytics, the predicted values are based solely on historical trends in your data.
In some cases, you might be able to improve the forecast by adding underlying factors. These are additional measures that you think might help improve the accuracy of your forecast.
As you add these additional measures, Visual Analytics evaluates them to determine whether they contribute to the accuracy of the forecast. If the additional measures do not increase the accuracy, then they are not applied. If they do increase the accuracy, then the contributing measure is highlighted in the Roles pane, the measure is used to adjust the forecast and the confidence bands are narrowed, the measure is displayed as a separate line in the forecast, and the What-If analysis button is enabled.
After underlying factors are identified, you can then perform what-if analysis, which looks at changes in the forecasts based on changes in your data from new information. There are two types of what-if analysis that can be performed: scenario analysis and goal-seeking.
With scenario analysis, you modify future values of the underlying factors to see what impact those changes have on the forecast.
With goal-seeking, you modify the future values of the forecast to see what changes in the underlying factors are needed to reach that goal.
Let's look at an example for each. Starting with scenario analysis: our underlying factor will be what I eat for dinner. I decide to eat all my favorite foods, and I want to forecast what my future weight will be.
Now let's look at goal-seeking. Here, I start with my goal which is I want to forecast my current weight minus 10% and I want the forecast algorithm to tell me what the underlying factor, i.e. what I should eat for dinner, should be.
When the What-If button is enabled on the Forecast object, you can select either Scenario Analysis or Goal-Seeking.
Let's look at the Scenario Analysis interfaces. You can toggle between either the table or chart to modify the future values of the underlying factor measure. In the table interface, you will see the current forecasted value and can enter a new value. In the chart interface, you can drag the marker to the desired value. Once you have made your data value edits, be sure to click the apply button to rerun the forecast.
You can also use the adjust menu to apply an adjustment to all of the underlying factor values. There is also a reset option available to reset to the original values.
Now let's look at the Goal-Seeking interfaces. You can toggle between either the table or chart to modify the future values of the forecast measure. In the table interface, you will see the current forecasted value and can enter a new value. In the chart interface, you can drag the marker to the desired value. Once you've made your data value edits, be sure to click the apply button to rerun the forecast.
You can also use the adjust menu to apply an adjustment to all of the future forecast values. In goal-seeking, there is an additional option to set bounds for each underlying factor to limit the minimum and maximum values that are possible. There is also a reset option available to reset to the original values.

=== Accessibility Tips 401 ===
Let's discuss some additional tips to keep in mind when designing accessible reports.
    These can be split into recommendations for objects, like list tables, geomaps, and animated
    objects, tips for improving report navigation, and guidelines when working with actions.


    Avoid adding totals to list tables.
    In the web application, screen readers do not see the totals.
    If totals are important, use a key-value object or add a text object with dynamic text that
    displays the totals.
    For list tables, when you use gauge display rule, be sure to include the measure that
    the rule is based on in the list table.
    This avoids accessibility problems for screen reader users and for users with color-deficient
    vision who might not be able to distinguish the difference between the gauge colors.
    For geomaps, beware of the color role and the link color role for geonetwork objects.
    For measures, the gradient used to color the regions often blends in with the background
    map, which can make it difficult or impossible for a person with color blindness to pinpoint
    the data.
    For categories, the default colors are different but have similar luminosities.
    This can make it difficult for people with color blindness to distinguish the values.
    Modify the color choices to use those that differ from the background map and have different
    luminosity.
    In addition, panning and area-based selection in geomaps are not accessible to keyboard-only
    users or screen reader users.
    To ensure that those users can see all data presented in the map, verify that the zoom
    level is sufficient.
    Avoid geocontour maps because they are not accessible to screen reader users.
    If you need to use a geocontour map, present the same data with another, more accessible
    object, like a list table.
    When working with animated objects, set the animation speed to slow or medium.
    This avoids rapidly flashing content that can violate accessibility guidelines.


    When using text objects to display a title, make sure that you mark the text as one of
    the available heading styles.
    Screen readers can perceive the text as a heading, which helps make the report easier
    to navigate and understand.
    However, be aware that in the iOS app, voiceover users cannot perceive that text content with
    a heading style as a heading, but they can perceive that object titles are headings.
    It's always a best practice to specify descriptive text for objects.
    Visual analytics will identify an object using alternative text, if any is specified, the
    object's title and the object's name.
    Choose meaningful titles or names for your objects, or specify alternative text.
    Always provide context for graph content.
    If you remove access labels, provide a title or description that explains the data items
    used in the graph.
    In general, including access labels improves your reader's ability to understand graphs
    in your report.
    It's always best to provide information to users about accessibility features.
    For example, the Visual Analytics web application includes several keyboard shortcuts that are
    useful for keyboard-only users and users of screen readers.
    Consider providing links to the keyboard shortcuts in the SAS Visual Analytics, Accessibility
    Features Documentation.


    Provide using link selection actions.
    This includes link selection between objects and automatic link selection actions.
    Screen reader users cannot perceive that there is a link selection between objects or that
    data elements within a graph are highlighted via a link selection action.
    Use text objects to explain report actions.
    Visual Analytics does not automatically provide information to screen reader users about actions.
    Both screen reader and sighted users might not understand interactivity, so including
    some explanation will be helpful to everyone.
    In addition, try to avoid complex chains of report actions that are difficult to explain.
    This ensures that your reports are easier to use for everyone, regardless of ability.

=== Choose the Best Chart 1116 ===
In the next step, choose the best chart. You start drafting the report based on your sketch.
    How do you know which chart type to choose? It depends on the data that you want to display,
    character, numeric, date, and so on, and what you are trying to showcase.


    Ask yourself these six questions to choose the best chart type.
    Am I highlighting one important fact? Am I comparing two or more things?
    Am I showing survey or questionnaire results? Am I describing how the parts relate to the whole?
    Am I showing relationships between data items? Is a graph required?


    Am I highlighting one important fact? If so, you can use a key value object or
    dynamic text to highlight a single number, a donut chart to highlight a single percentage,
    or a faded bar chart that draws the viewer's attention to one value.


    For the pie chart and the bar chart, display rules are used to highlight important values.
    When doing this, take care to choose colors that are easily distinguished, especially for users who
    are color blind. You can test whether your color choices are accessible to users with
    color-deficient vision by changing your display to grayscale mode or printing the report in grayscale.


    In addition, when you use expression-based display rules, it's a best practice to
    specify a meaningful label for the display rule. This label appears in the display rules
    pane when viewing the report and in the toolkit for any elements to which the display rule applies.
    This label is also announced by screen readers in the Visual Analytics web application.


    Am I comparing two or more things? For general comparisons, use a bar chart to
    compare multiple pieces of data, a dot plot to compare groups with values close together,
    a butterfly chart to compare two groups across different categories, or a dual-axis chart to
    compare two measures with different ranges. However, be aware that some audiences might
    not be familiar with dual-axis charts and might misinterpret them. It might be better to show two
    single-axis graphs instead.


    Fixed-axis ranges can be useful for accessibility because they enable
    users of sonification to understand the scale of data that is shown in the object. This is
    especially useful when the values shown in the object can change due to filtering or drilling
    down in a hierarchy. However, if your data updates frequently or is likely to fall outside the range
    when filtering or drilling, a fixed-axis range is not recommended because values can unknowingly
    fall outside of the fixed range.


    Am I comparing two or more things? For comparisons over time,
    use a line chart or a time series plot.


    For these types of charts, an option is available
    for adding an overview axis to the chart. The overview axis is a scrolling axis that enables
    you to specify how much of the axis appears and which segment of the axis appears. These can make
    it easier to focus on specific time periods in the chart. Be aware that screen readers cannot
    interact with the overview axis. If you need to include an overview axis, include a second object,
    like a list table or cross tab, that presents the same information in an accessible way or
    direct users to the details table that is displayed when the object is maximized.


    For line charts or time series plots that include groups, multiple lines are displayed on the plot.
    Visual analytics includes support for line patterns to distinguish between lines in a line chart.
    Users can turn on line patterns by setting the high contrast report theme override setting for
    the report. Report authors do not need to do anything to make this setting available to users,
    but it is a best practice to include a note that specifies how to override the theme with the high
    contrast report theme.


    Am I comparing two or more things? For comparing against a benchmark,
    add reference lines or display rules, use a needle plot, use a bullet gauge for its simplicity,
    or create a targeted bar chart.


    Some objects, like gauges, use a gradient for colors. Avoid
    three color gradients, that is, gradients that vary from one color at one end of a range,
    to a second color in the middle of the range, to a third color at the opposite end of a range.
    Three color gradients are generally not accessible to people with color deficient vision. Instead,
    use two color gradients and choose starting and ending colors with a sufficient difference
    in luminosity. It's a best practice to use the default colors or choose colors that appear in
    the same vertical column in the standard list of colors. Each color in a column has a different
    luminosity and can be distinguished by people with color blindness. You can test the gradient
    by turning your display to grayscale mode or by printing the report in grayscale.



    Am I showing survey or questionnaire results? If so, you can use a stacked bar chart to compare
    Likert responses, like never, occasionally, sometimes, often, or always, a vertical bar chart
    or column bar chart, for all that apply questions or a table or crosstab if the viewer needs to
    compare specific data values or precise numeric values are needed. Box plots can also be useful
    to show the average response, the minimum and maximum values and outliers. However, many people
    are unfamiliar with box plots, so it might be helpful to provide an explanation.

 
     For bar charts
     that contain groups, different colors are used for each group. Visual analytics includes support
     for fill patterns to distinguish between groups in a bar chart. Users can turn on fill patterns
     by setting the high contrast report theme override setting for the report. Report authors do not need
     to do anything to make this setting available to users, but it is a best practice to include a note
     that specifies how to override the theme with the high contrast report theme. In addition,
     it's a best practice to avoid adding display rules to objects that use color to distinguish
     between groups, like grouped bar charts. The display rule overrides the fill pattern,
     which might make it difficult for viewers to distinguish the elements.
 

    Am I describing how the parts relate to the whole? If so, use a donut chart or a pie chart
    if comparing only four or five data points, a stacked bar chart, a histogram to show ranges
    and intervals, a tree map or a geomap when location is an important part of the analysis.


    Pie charts should be used only to compare a few groups, five or fewer. Pie charts are popular,
    but be aware that it is very hard to compare the relative sizes of slices in the chart.
    In addition, changes over time are difficult to detect, and pie charts take up more space
    than any other types of charts, like bar charts and tree maps. Because of this, pie charts should
    be used sparingly and only in special circumstances. Specifically, you can use a pie chart to illustrate
    that one value makes up the majority as seen in this pie chart, which might be difficult to detect
    in a bar chart.

 
     Donut charts are similar to pie charts but have a hole in the center that can
     display an abbreviated total. This hole makes it easier to compare relative sizes because it forces
     the viewer to focus on reading the lengths of the arcs rather than the proportions of the slices.
     Be aware that when the donut chart includes a donut hole label, as seen in this donut chart,
     the label is not accessible to screen readers in the Visual Analytics web application.
     If you use this type of label to convey information to your viewers,
     you should include the same data in an alternative way, like with a text object or a list table.
 

    It's best to use pie charts and donut charts sparingly or not at all. In most cases, you can
    display the same information more clearly in a bar chart. Don't take it from me, though. Here's
    what the visualization experts have to say about pie charts.

 
     Geomaps can be used when location is
     an important part of the analysis, but they can be difficult for many users to interpret.
     Consider supplementing geomaps with more easily understood objects,
     like list tables or cross tabs. In addition, be aware that text labels for place names might
     have insufficient contrast against the background map. To improve accessibility, use the automatic
     map background, which updates to a high contrast map when the high contrast report theme is used,
     or use the open street map high contrast background.
 
 
     Am I showing the relationship
     between data items? If so, use a scatter plot or a heat map to show the relationship between two
     variables, a bubble plot to show the relationship between three variables, or a correlation matrix
     to show the linear relationship between many measures. For readers using screen reader
     technology, it's a best practice to limit digits displayed after decimal points unless it's required
     for precision.
 
 
     Am I showing the relationship between data items? You can use a network diagram
     to show many relationships, a path analysis to show processes, or a text object to add
     a detailed description when no visual is possible. For example, if you want to display numbered
     lists or bullets, when using these types of charts, it's especially important to ensure that
     legends are displayed on all screen sizes. If legends are not displayed on the chart,
     they can be viewed only when the user activates the collapsed button. The button does not have
     an accessible name or role, so it is not useful for screen readers.
 
 
     Is a graph required? In some
     cases, word clouds, images, or illustrations created with the data-driven content object
     might better communicate the point. In addition, text can be used to give context to the value or
     state the conclusions that can be drawn from the data. When using text, avoid using sensory
     characteristics like the size of the object, the shape of the item, or the position on the screen
     as the sole means of conveying information or identifying a portion of the report.
     This can make it difficult for screen reader users to navigate the report.
 

    Word clouds can be used to easily identify commonalities or common values in your data.
    However, word clouds should be avoided if analytical accuracy is desired because the
    size and position of the word can impact the attention placed on the word.
    Typically, users find word clouds easier to comprehend if you limit the number of words
    displayed. This can be done with the word display limit option. Avoid using the color
    role in the word cloud. Assigning a measure to this role can produce low-contrast text that is
    difficult to read.


    The image object can be used to include graphics in your report,
    like the corporate logo, diagrams, or a background image. When you use an image,
    it's a best practice to specify alternative text to identify the image object for screen reader
    users. If the image is complex and needs more than a brief sentence to describe,
    consider placing a text object next to the image and add text that conveys equivalent
    information for these users.


    The text object is a useful way to provide context or to state the
    conclusions that can be drawn from the data. Be aware that screen readers cannot perceive
    text formatting, like font, text size, foreground color, background color, weight, italic,
    underlining, or justification. Avoid using text formatting, including text color,
    to convey meaning unless you also describe it in the text itself.

=== Choose the Best Control 206 ===
When adding prompts to your report, you need to select the best control for your data.
    One option is to use auto controls. Auto controls can be created by dragging data items to the
    report or page prompt area. Visual Analytics chooses the appropriate control based on the type,
    category, date, time, or measure, and the cardinality of the data item. If you drag a
    hierarchy to the report or page prompt area, the auto control chooses the best control object for
    each level of the hierarchy, and automatic filters are added to create cascading controls.


    Alternatively, you can select your own control object. When selecting control objects,
    you need to consider the type and cardinality of the data item.
    For date and measure data items, a slider control should be used. This control enables a viewer to
    move a selector horizontally or vertically to select a single value or a range of values.
    For category data items, the control that you use depends on whether you want the viewer to
    select multiple values or a single value. To select multiple values, a list control should be used.
    This control enables a viewer to select one or more category values from a list.
    The list control can be used only in the report and page prompt areas inside a prompt container
    or when the report and page prompt areas are on the left or right of the canvas.


    To select a single value, you also need to consider the cardinality. Remember that the
    cardinality measures the number of distinct values for a category data item. Categories
    with few distinct values, that is, fewer than five, can be used with a button bar. A button
    bar displays buttons in a vertical or horizontal layout. Categories with a moderate number of
    distinct values, between five and 40, can be used with a drop-down list. Categories with many
    distinct values, that is, more than 40, can be used with a text input control. A text input
    control enables a viewer to enter text in a field. As text is entered, the list of available values
    is filtered.

=== Consider the Layout 804 ===
Remember that the goal of reporting is to tell a single data story.
    In the next step, consider the layout.
    You need to arrange the pages and objects in the optimal way to convey your message.
    Keep these best practices in mind.
    Limit the number of data sources, pages, and objects.
    Make more important objects larger.
    Consider the placement of objects.
    Arrange objects with actions in a logical order.
    Use negative space.
    And use the default grid layout or containers.


    Limit the number of data sources used in the report.
    Recall that each report can use data that exists in multiple tables.
    Although there are no specific limits to the number of data sources that can be used in a report,
    as a best practice, each report should use three or fewer data sources.
    This will keep your report from covering too many topics.
    Limiting the number of data sources used in the report can also improve the performance of the report.
    If you need to use more than six data sources to tell your data story,
    consider combining data sources in the data preparation phase.
    Although this can be done in visual analytics by creating an aggregated data source or a data source join,
    it's recommended that you prepare your data before using it in the report,
    for example, by writing code in SAS Studio.


    Limit the number of pages used in a report.
    There are no technical limitations to the number of pages that can be added to a report.
    However, if you need more than six or seven pages to tell your story,
    consider breaking the story into multiple reports.
    Using fewer pages makes the report seem less complex
    and makes it easier for the user to remember the content presented on each page.
    Limiting the number of pages can also help with the performance of the report,
    especially if the report is viewed on a mobile device.
    Arrange pages in a logical order that will advance the data story.
    Also, consider adding a table of contents with links to each page for easy navigation
    or adding an introductory page with useful information,
    like the company logo, the update schedule, contact information, or a summary of the report.
    You can also use page links to control the navigation of the report
    or to provide additional details with pop-up pages.
    This will reduce the chance of overwhelming users with details
    and can also help with accessibility by giving viewers an alternative view of the data.


    Limit the number of objects on each page.
    Although there are no physical limits to the number of objects that can be added to each page,
    it's a best practice to use between two and six objects per page.
    This enables the user to focus on the data and can improve comprehension.


    Make more important objects larger.
    You can enhance visibility by making more important objects larger and less important objects smaller.
    The larger the graph or chart, the more time that the audience spends studying it.
    In this example, the geomap takes up almost 75% of the screen,
    and the key value objects share 25%.
    When accessing this report, the viewer will spend more time looking at the geomap
    and use the key value objects for additional information.
    Once you have created pages that meet your specifications,
    you can save them as a page template and reuse them in other reports.
    This helps speed up development time in the future.


    Consider the placement of objects.
    Placing an object in the center of the page or in the top left corner can create a focal point.
    However, this placement might change depending on the location of the audience.
    In the example on the left, the needle plot is placed in the center of the page, near the top.
    As a consequence, the viewer views that chart first and uses the other objects for supplemental information.
    Also be aware that objects that are side-by-side or on the same row or column are intuitively understood to be related.
    In addition, you should arrange objects so that different pieces of related data are next to each other for easy comparison
    and not far apart.
    In the example on the right, all objects related to South America are in one column,
    and all objects related to Europe are in a second column.
    In addition, rows are created to hold the key value objects and the bar charts
    so that they are easily compared across continents.


    Arrange objects with actions in a logical order.
    The source object should be placed in the upper left corner
    and the target objects should be placed to the right of and below the source object.
    In this example, the list control in the upper left corner is the source object.
    When the viewer selects a continent, the geomap in the upper right corner is filtered.
    Then when the viewer selects a country in the geomap, both the bar chart in the lower left corner
    and the list table in the lower right corner are filtered.
    Lastly, when the viewer selects a bar in the bar chart,
    the associated row in the list table is highlighted with a linked selection action.
    Recall that the linked selection action will work in both ways,
    the viewer can select a row in the list table and highlight the associated bar in the bar chart.
    Notice how objects are arranged to match the path of actions from left to right, top to bottom.
    Be aware that this arrangement will change for cultures that read from right to left.


    Use negative space.
    Negative space can be used to increase comprehension and enable easier navigation of the report.
    It also makes for a more visually appealing and elegant report.
    Increase negative space, avoid borders and use margins and padding, but remember to be consistent.
    In the example on the right, padding is reduced and objects are overlapping.
    This makes for a report that appears too cluttered and can overwhelm the audience.
    The example on the left contains the same information but uses default padding.
    This report exudes a more relaxed impression, and it's much less likely that viewers will miss important details.
    In addition, be aware that larger amounts of padding can crowd report content when users view the report on small screens or with zoom set above 100%.
    If you modify the amount of padding, ensure that you test the report thoroughly.
    Too small padding can cause the keyboard focus indicator to appear oddly or not at all.
    If you change the amount of padding from the default, test the report on smaller screens or with a higher zoom.
    In addition, test the report as a keyboard user to ensure that report content is still usable and keyboard focus indicators are still visible.


    Use the default grid layout or containers.
    The default grid layout and the standard container enable you to place objects directly next to other objects without overlap.
    All objects are sized to fill the user's screen.
    You can easily resize objects using the 4x8 grid.
    For greater accuracy, you can press and hold the control key to increase the resolution of the grid.


    Alternatively, you can use containers to group objects.
    The prompt container can be used to organize multiple prompts and can be beneficial to mobile device users by enabling easier navigation.
    The scrolling container enables you to create a report that functions like a web page.
    You can add more information and graphs can be larger, which can improve the viewing experience on a mobile device.
    This layout also enables more clarification of objects because it enables you to add text to describe the object or text that includes additional information.


    The stacking container can be used to group related objects.
    The stacking container can also add an alternative way to view the same information in different ways, like by including a table or a more mainstream chart.
    This helps with accessibility, especially for users who use screen reader technology.


    You can also use precision containers to create a report with overlapping objects, like to add a background image to the report.
    Be aware that precision containers can cause problems when reports are viewed on different screen sizes.
    If you want to use them, it's recommended that you use the report level option set fixed report size to specify a fixed size of the report.
    However, if you use this option, be sure to test thoroughly on multiple devices and screen sizes.

=== Draft a Plan 325 ===
When drafting a plan, you need to, one, select your data, two, know your audience, three,
    craft your story, and four, sketch your design.


    You'll start by selecting your data.
    This data can be stored in any format, SAS data sets, Microsoft Excel files, database
    tables, text files, and can even exist in multiple tables.
    You can combine the tables before using them in Visual Analytics, or you can use multiple
    data sources in your report.
    The update frequency of the data sources that you choose determine how often the report
    is updated.
    As a best practice, we recommend that you prepare your data before using it in Visual
    Analytics, for example, by writing code in SAS Studio.
    You can also create a variety of data items in Visual Analytics using one-click calculations,
    like the difference from the previous period or distinct count, hierarchies that enable
    you to view different levels of the data, geography data items for mapping, parameters,
    to enable dynamic control by the report viewer, and statistical data items like interaction
    effects, spline effects, and partitions.


    Then you need to determine the audience for your report.
    The needs and interests of your audience determine what you present, how you present it, and
    what level of detail you include.


    Suppose you are building a report for statisticians.
    You might use models and advanced analytics in the report, like the automated explanation,
    automated prediction, forecasting, network analysis, path analysis, and text topics.
    For this audience, those models will be self-explanatory, and you might not have to include a lot of
    detail about how the model works, the purpose of the model, and why it's useful for the
    report.
    On the other hand, if you are building a report for a general audience, you might want to
    use simpler graphs that are easier to interpret and understand.
    In addition, you might want to include additional instructions and explanatory text to explain
    the purpose and usefulness of the report.


    Your audience will also give you a good idea about whether you want to enable the viewer
    to modify pieces of the report, like modifying simple options and sorting, changing the report
    object, or changing the data used in the report.
    You can control their level of modification by setting the customization level for the
    report.


    You also need to start crafting your data story.
    Your reports should focus on telling a single data story.
    When you begin to craft your story, think about these questions.
    Are you trying to persuade your audience?
    Are you presenting facts?
    Do you want the audience to act?
    Storytelling helps your audience feel connected to your report by eliciting emotion and triggering
    memory.
    This makes it more likely that they will remember what the report has to say and will
    act on those findings.


    Finally, you should do a rough sketch of the design of the report.
    This can be an outline of the report, a table of contents, or a draft of each page, which
    includes a rough layout, the types of objects that will be used, and how each page contributes
    to your overall data story.
    You should always keep the story in mind when building your report.
    In this stage, you should also start planning for accessibility.
    For example, you can plan to add a table representation for each graph to better enable viewers to
    see specific values.

=== Focus on Whats Important 510 ===
In the next step, focus on what's important, you need to make sure that your report is
    compelling and interactive and that it enables viewers to find the information that is important
    to them when they need it.
    This means that you need to create reports that are well organized, easy to navigate,
    versatile, and attractive.


    You can organize content by adding multiple pages to your reports.
    Each page in your report should focus on one aspect of the story and tell that piece with
    a limited number of objects.
    Not only that, but you must ensure that each page can stand on its own.
    Viewers should not be expected to remember details from one page to understand the concepts
    that are communicated on another page.
    In addition to adding multiple pages to your report, you can create pages that provide
    additional details to report viewers, hidden pages, and pop-up pages.
    These pages can be used to communicate details about the report to other designers, or they
    can be linked to from an object on a regular page to enable viewers to see additional details.
    There is no limit to the number of pages that can be added to a report or the number of
    objects that can be added to a page.
    However, it is a good idea to limit the number of pages to make your report easier to access,
    easier to navigate, and easier to understand.
    If you need more than six or seven visible pages to tell your data story, you should
    consider creating multiple reports and use links between them to provide additional information.



    You can make your reports easy to navigate by adding descriptions to define the purpose
    of your report and instructions to describe the features of the report.
    Use clear, detailed titles that help your audience understand the purpose of the object,
    and use text to add additional details and numbers when needed.
    Add a table of contents or an introductory page to help explain the basics of the report.
    You can even use pop-up pages to provide more information about navigating the page,
    like detailed tips on how to use each page, descriptions of report objects, and information
    about actions and links.
    This information can be communicated with a text object or even a video.
    Including detailed descriptions and instructions can help make the report more accessible and
    is critical for any users who will interact with the report using screen reader technology.
    Adding text to explain report actions will enable screen readers and sighted users to
    better understand the structure of the report.
    When adding text in titles or instructions, or for explanations, it's a best practice
    to use consistent fonts.


    You can make your reports versatile or interactive by adding animations, ranks, prompts, actions,
    and links, and by setting viewer capabilities.


    Animations can enable your users to view changes in data over time.
    When using animations, be sure to focus on changes that are different from the norm.
    Ranks enable users to focus on the most important values and can be used to identify leaders,
    top values, or lagers, bottom values.
    Report and page prompts can be used to help the viewer focus on areas that are important
    to them by filtering the report and page, respectively.
    Consider the placement of prompts because you don't want them to be overlooked and
    use titles to explain their purpose, how to use the prompt, and which elements are
    affected.


    Actions can add interactivity to the report so that users can explore data in a way that
    is meaningful to them.
    This involves them in the data discovery process and increases their motivation to act on their
    findings.
    Using automatic actions enables users to customize their experience by specifying the order in
    which their actions are applied, making the report more dynamic and valuable.
    Automatic actions can also be a useful way to speed up development.
    Links can be used to provide additional information.
    Be sure to add instructions to explain which links are available and how they work.
    For example, whether they filter the target data.
    Viewer capabilities enables you to give users more control over the appearance of the report
    by modifying options, changing chart types, or selecting the data.


    Finally, you can add styles and display rules to make your reports more attractive.
    Styles can be modified at the report level, at the page level, and at the object level.
    You can specify the background color, the font, the colors for objects, like fill, lines,
    markers, and gradient, the data skin, and you can add padding and borders.
    However you choose to modify styles, be consistent.
    Using too many different styles detracts from the message of your report.
    Display rules can be used to highlight important values.
    Be sure to choose colors that are easily distinguished, especially for users who are
    color blind.


    When working with colors, be cognizant of color choices.
    The choice of color can affect the mood and the viewer's reaction to a report object.
    Colors can evoke both positive and negative emotions.
    For each color choice shown, the words on the left list the positive associations with
    that color, and the words on the right list the negative associations with that color.
    Be aware that your color choices might change for different localities or regions.

=== Lesson Overview 038 ===
To enable viewers to find the information that is important to them, you need to create compelling, interactive reports. You can do this by designing a report that is both visually appealing and easy to understand. For more information about how to create effective reports, including examples, guidelines, and references, visit www.sas.com/beautifulreports.
To create an impactful report, follow these steps: (1) draft a plan, (2) choose the best chart, (3) focus on what's important, (4) consider the layout, and (5) test, test, and test again.

=== Test Test and Test Again 535 ===
In the final step, test, test and test again, you evaluate the performance and accessibility
    of the report, solicit feedback from colleagues, test the report on multiple devices, screen
    sizes and presentations, and view the report using different languages.


    You can use the report review pane to evaluate the performance and accessibility of your
    report.


    Any issues that are identified include a description and suggestions for improvement, and they
    are categorized into high, medium, or low severity.
    For some suggestions, like unused data sources, object names, and unused data items, you can
    click the More button to perform additional actions on the issue.
    For example, if the report contains an unused data source, you can use this menu to delete
    the data source.


    If performance is an issue, consider reducing the number of pages in the report, reducing
    the number of objects on a page, reducing the number of controls in the report or page
    prompt areas, using fewer data sources, decreased usage of nested containers, pre-aggregating
    or joining your data, removing unnecessary data items in the data preparation phase,
    or pre-filtering the data.
    These performance improvements can be especially useful for users who view the report on a
    mobile device.


    For accessibility, limit the use of animation, color-dependent display rules, lattices, linked
    selection actions, and overview axes.
    In addition, for screen reader users, provide meaningful names or titles for objects or
    specify alternative text.


    In addition to viewing issues on the Report Review pane, you can use the Report Review
    menu button to create a PDF of a list of all issues analyzed, whether the report passed
    each check, a list of priorities for issues detected, and recommendations for improvement.
    For more information about the issues and thresholds, see the Report Review pane reference
    in the SAS Visual Analytics documentation.


    In addition to using the Report Review pane to analyze the performance of a report, you
    can also use an internal diagnostic tool to troubleshoot report data issues.
    When editing the report, press Ctrl plus Alt plus Q to access the Query Diagnostics window.
    From this window, you can select an individual object from the report and execute the query
    to check its run time.
    This can help you pinpoint long-running queries, like those that include calculated items,
    and might point toward possible solutions.
    For example, if an object that uses calculated items has a long-running query, you might
    be able to increase report performance by calculating the data items during the data
    preparation phase.


    To improve the performance of your reports, heat these best practices in mind.
    Reduce the usage of complex filters.
    You can do this by moving static filters to the data preparation phase.
    Do not create reports that use too many data sources.
    If your reports need more than six data sources, consider joining the tables in the data preparation
    phase.
    Limit the number of objects per page.
    In general, each page should use fewer than six objects.
    Consider breaking these pages into multiple pages and using links to move between them.
    Limit the use of complex calculations.
    Some calculations can be moved to the data preparation phase.


    Then, ask colleagues for feedback on your report.
    Ask them the following questions.
    What is the story?
    Is the report easy to navigate?
    Did you get lost?
    Did all the actions work?
    Were all the features of the report apparent?
    Use their feedback to make your report even better than it was before.


    Finally, test your report on various devices and screen sizes.
    You can do this using the developer tools for your browser and clicking the toggle device
    toolbar button.
    This enables you to view and navigate the report using different devices and different
    screen sizes.
    This is especially important if the precision container was used in the report because the
    objects can look different on different screens.


    You should also perform other tests, depending on how your report will be used.
    For example, you should create a PDF of the report if the report will be shared via report
    distribution.
    You can also perform a test print of the report if users will be printing hard copies.
    When doing this, print the report in grayscale to check that users with low vision or color
    blindness can identify color differences.
    You can also project the report to ensure that the colors show up and have sufficient
    contrast.
    View the report using the SAS Viya SDK for JavaScript if report content will be embedded
    in a custom webpage.
    Test the report from SAS for Microsoft 365 and play the report if it will be presented
    in a kiosk or as a slideshow.


    To set up report playback, view the report, click the report toolbar and select edit playback.
    Options are available to hide the report control area, page tabs, and page report area, show
    canvas only, to show a timer for each page, show timer, and to show navigation controls
    for the report playback, show navigation controls upon click or touch.


    You should also test the report when the application colors are inverted, using control plus grave,
    and when the viewer chooses to override the theme with the high contrast report theme
    as users can use this option to view the report at higher contrast.
    In addition, if the report has been localized, you might want to view the report using browsers
    with different locales.
    If you choose to localize reports, make sure to localize all available text.
    This helps avoid problems with mixed language content.
