## Setup bug (found before the browser run)
**A fresh `docker compose up` cannot load demo content.** Compose mounts `postgres/init.sql` into `docker-entrypoint-initdb.d`, so Postgres creates the app tables before the backend boots. `app.main._run_alembic` then sees "app tables, no `alembic_version`" and stamps HEAD without running revisions, trusting `create_all` + `_migrate` to fill the gap. But 8 columns added only by Alembic revisions are in neither `init.sql` nor `_migrate`:

`analysis_results.run_id`, `analysis_results.params`, `analysis_results.created_by`, `dataset_columns.source_column_id`, `datasets.aggregate_of_dataset_id`, `datasets.aggregate_spec`, `report_pages.background_url`, `reports.origin`

Reproduced live: `POST /api/v1/demo/seed` → 500 (`UndefinedColumnError: column datasets.aggregate_of_dataset_id does not exist`). An empty database (Alembic `upgrade head`) works and seeds 6 datasets / 8 dashboards / 121 widgets. Fix: add an `ALTER TABLE … ADD COLUMN IF NOT EXISTS` line to `_migrate` for each column (or bring `init.sql` up to date). The new test lists the missing columns and passes once they are covered.
