### Task T1: Alembic migrations (adoption-safe)

**Files:** Create `backend/alembic.ini`, `backend/alembic/env.py`, `backend/alembic/versions/0001_baseline.py`. Modify `backend/app/main.py` (startup), `backend/requirements.txt` (+alembic). Test `backend/tests/test_alembic_migrations.py`.

**Semantics — adoption without breakage:**
- `env.py`: async engine from the app's settings; `target_metadata = Base.metadata`.
- `0001_baseline` = autogenerated snapshot of CURRENT `Base.metadata` (generate against a scratch DB, then hand-check it imports cleanly; do not hand-write 50 tables).
- Startup (new `_run_alembic()` in main.py, wrapped/logged/never-brick, running BEFORE create_all/_migrate):
  - If DB has no `alembic_version` table AND existing app tables → **stamp** baseline (adopt live DBs without touching schema).
  - If no app tables → `upgrade head` (fresh DB path).
  - Else → `upgrade head`.
- KEEP create_all + `_migrate` this cycle (belt-and-braces; they are idempotent). Future schema changes go through revisions; add a `backend/alembic/README.md` one-pager saying so.
- Tests: fresh SQLite → upgrade head produces the same tables create_all would (compare `Base.metadata.tables.keys()` vs inspector); existing-DB adoption path stamps without altering; double-run idempotent; startup survives alembic throwing (monkeypatch).

### Task T2: Declared-FK seeding (Layer 1 stage 4.1)

**Files:** Modify `backend/app/services/metadata/sync.py` (the relationship stage), models if `relationships` lacks a needed field (grep: it has `source` provenance — inferred|confirmed; add `declared` as a value, no schema change expected). Test `backend/tests/test_declared_fk_seeding.py`.

**Semantics:** during sync against a live SQL source, read real foreign keys via SQLAlchemy `inspect(engine).get_foreign_keys(table)` per synced table. Single-column FKs only (repo constraint: relationships are single-column). Each becomes a relationship row with `source='declared'`, confirmed-equivalent trust (whitelisted for the agent's join path exactly like `confirmed` — grep `agent/context.py` join whitelist and include `declared`). Seeding wins over inference: if an inferred row exists for the same pair, upgrade it to declared; a declared row is never downgraded by later inference. Composite FKs skipped with a debug log. Resync idempotent.
**Tests:** FK on a scratch SQLite/DuckDB source → declared row; inferred→declared upgrade; composite skipped; join whitelist includes declared; resync no-dup.

### Task T4: Feedback table + scheduled eval gate (Layer 4)

**Files:** Modify models (+`AgentFeedback`: id, org_id, user_id, conversation_id FK, run_id nullable, rating `up|down`, comment Text nullable, created_at; alembic revision 0003 + `_migrate`), `backend/app/routers/agent.py` (+`POST /agent/conversations/{id}/feedback`, org+owner-scoped: only the conversation's user may rate; upsert per (run_id,user)), frontend agent chat surface: 👍/👎 on answers (grep the agent conversation UI component). Scheduled gate: new `backend/app/services/eval_schedule.py` — an opt-in job registered with the existing in-process scheduler (grep `refresh_scheduler` registration pattern): when `settings.eval_gate_enabled` (config.py, default False) it runs `evals.run_gate` main-equivalent in-process against `settings.eval_gate_source_id` on a nightly cadence, writing one row to a small `eval_runs` table (id, started_at, finished_at, accuracy, passed, detail JSON) and logging loudly on regression below `settings.eval_gate_min_accuracy` (default 0.5). No CI pretense — this is the stand-in and says so in its docstring.
**Tests:** feedback CRUD + scoping (other user 404, upsert not dup); disabled-by-default (no job registered when flag off); enabled path runs a stubbed gate (monkeypatch run_gate to a canned result) and writes `eval_runs`; regression logs at ERROR.
