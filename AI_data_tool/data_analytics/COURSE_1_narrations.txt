=== Custom Categories 300 ===
A custom category allows you to create labels for groups of category or measure data items. Depending on the source data item, you can define a custom category using intervals or the distinct values of the data item. You can also use calculated items as the source.
Custom categories provide similar functionality to a user-defined format (UDF) but without the requirement of having to load the format with the data into CAS.
In this example, the data source has the Facility Opening Date data item. I would like to create a label for the group of facilities that were opened in the 1980s, 1990s, 2000s, and then the newest facilities.
Let's look at how to define a Custom Category Based on a Category data item. In this example, I will right-click Facility Opening Date and select New custom category. Next, I will enter the name of my first value group, Facilities opened in 1980's. Then, I will select the distinct values that I want to be included in this group. Then I will repeat this for any additional value groups. And finally, I will need to determine how to define the remaining values. The Show as is option is available only for data items that are based on string categories. It is not available for numeric or date values. For numeric or date values, I can choose to show the remaining values as missing or I can group them as other and give it a customized name.
Now let's take a look at defining a custom category based on a measure using intervals. I will also use the New data item menu this time and select Custom category. Using this click-path will mean that you will need to select the data item that you want the custom category to be based on. Next, because this is a measure data item, we need to select group by type. In this example, we will select Intervals. Next, we will need to name our Value Group and define the interval of values to be placed in this group. Repeat these steps for the other value groups. Notice the bar chart on the right that will show you your value group names and the distribution of the data item's values. There is also an option to use the Generate groups feature. Here, you can select from Automatic, 5, 10, or 15, or you can manually type the desired number of groups. Note that right now interval values are manually entered and cannot be dynamic yet.
Here is a look at defining a Custom Category Based on a Measure data item but this time using Distinct values. The initial steps to create the custom category are the same, by selecting the New data item menu and clicking Custom category. Next, you have to select the Based On data item. Then this time we will select to group by Distinct values. Name the value group and select the distinct values to be in that group. It is important to note that if you use Distinct Values, for either category or measure based on definitions, new values that appear in the data are grouped with the Remaining Values until added to a Value Group definition.

=== Data Item Properties 501 ===
In the Data pane, once you have selected a data source you will see all of the data items from the data source. Visual Analytics will automatically generate frequency and frequency percent. You can manually create categories, geographies, hierarchies, measures, parameters, and aggregated measures from the new data item menu.
At the top right of the data menu, you can click on the overflow menu. Here, the Show or Hide Data Items window gives you control over what data items you can see in the Data pane. You can hide data items to limit the amount of "noise" for business users, hide underlying data items used in calculations like ISO codes, latitude and longitude, or to limit the available data items shown to users who are viewing the report with Data edits Viewer Capabilities.
When you hover over a data item, it displays several tooltips. It lists the basic data item properties: name which is what we see in Visual Analytics but is actually the label in the data source name in the data source; format; and aggregation. It also gives information about whether the data item is used in data mappings, hierarchies, objects, filters, calculated item, display rules, or ranks.
There are additional tooltips for calculated data items and aggregated measures. The hover over and expanded properties will show the first five lines of the expression definition.
Use the chevrons to expand and collapse the data item properties pane. Note that modifying data item properties will impact all objects that use that data item.
A data item's classification in Visual Analytics provides the rules around how the data item can be used in the report. Data items coming from the raw data source can be a measure, category, or date/datetime. Not all data item classifications can be interchangeable, and a single data item cannot have more than one classification. If you need to use a data item in more than one classification type, then you will need to duplicate the data item to support two classifications.
A measure data item can be changed to a category or geography classification. A category data item can be changed to a geography classification. And a date/datetime data item cannot be changed from its classification.
Note that a data item classification cannot be changed if it is used by one or more report objects.
By default, all measures have a default aggregation of SUM. Use the Aggregation property to modify a measure's default aggregation behavior.
Use the Format property to modify a measure's format.
Visual Analytics has over thirty different local and international currency formats available. Be sure to verify that the format you select is as expected by using the Sample preview in the bottom corner.
SAS treats dates, time, and datetime data items as numbers. SAS uses formats to style the numeric value into what we consider a Julian calendar date or time using a 24-hour or 12-hour clock. A date data item is the number of days since January 1, 1960. A time data item is the number of seconds from midnight of the current day. And a datetime data item is the number of seconds since midnight January 1, 1960.
The available date/datetime formats will depend on the source data's granularity. A SAS datetime is the number of days, seconds, and milliseconds since January 1, 1960. A SAS date format is used to make the number appear as a Julian calendar date.
Note that many periodic calculations require a format that includes a year.
Use the selection boxes to multi-select data items to bulk change classifications, aggregations, and formats.
Use the selection boxes for quick and easy data item multi-selection, and the bottom Clear selection to deselect. The data item overflow menu offers data item actions that can be applied in bulk.
You can also use the data item overflow menu and the Select option to quickly select data items with the same attributes to take actions on, such as selecting all the measures, or all categories, or all measures with the same format or aggregation.
Duplicating data items is the fastest way to create measures with different aggregations or date/datetime data items with different formats. First, you right-click a data item and select Duplicate. Second, expand the data item properties and edit the data item name and format. The newly formatted data item will display in the Data pane.
You can delete only the data items that you create in the report. You cannot delete a raw data source item. Also, you cannot delete a data item if it is used in the report in any manner. If you do not want to see a raw data source item listed in the Data pane, then use the Show or Hide Data Items menu.

=== Data Views 536 ===
This Visual Analytics data view is not the same as a database view, which is a query executed when the table is referenced. In Visual Analytics, after a data source is added to a report, there are often many changes, additions, or modifications that are made to the data source. These changes are tied to a data source and can be saved in what is called a data view. The data view is sharable between users and can be applied to only its associated data source.
The settings that can be stored in a data view are data item settings such as names, formats, classifications, aggregations, data source filters, hierarchies, calculated items, custom categories, duplicate data items, show and hide statuses for data items, unique row identifier selections, and any parameters that the data source depends on.
Let's look at the steps to create a data view. First, make the data source changes that you want to save. In this example, I create a new hierarchy. Second, you must save the data view. Use the Data source menu and select Save data view. Then give your data view a meaningful name and save.
Now let's look at how to apply a data view. Third, you must create a new report. Fourth, select the data source. Fifth, use the Data source menu and select Manage data view. Then select the data view that you want to apply. Sixth, assess the message and select whether you need to decide how to apply each data item in the data view or you can continue applying the data view. Last, you can see that the hierarchy that we saved in our data view has been added to the Data pane.
Here are key data view behaviors to keep in mind. A data source can have more than one data view. You can create one data view per setting change, or you can have many setting changes saved in a single data view. You can add multiple data views per data source. Use caution when applying multiple data views so as not to overwrite any settings accidentally. There is no indication in Visual Analytics to let you know whether a data view has been applied. If there are data item conflicts in the Data pane and the data view being applied, a user interface provides resolution options. In this example, you can see that the hierarchy and MPG (City) (1) were added to the Data pane, but MPG(Highway) was replaced.
If you select the option to decide how to apply each data item with conflicts, then you are presented with this user interface. The data items with conflict are listed and under the How to Apply column, you can choose to add as the listed name (usually the name of the data item with a number in parentheses), ignore the incoming data view data item, add the incoming data view data item, or replace the selected data item with the incoming data view data item. Once you make your selection, you can use the information button to see the settings saved in the data view in the report, and what action applying the data view will take.
A default data view is automatically applied when the data source is added to a report. There are two types of default data views: one, where the default data view is defined by the user and two, where the default data view is defined by the administrator.
Any user can set a user-defined default data view. The default data view is available only to that user. And the default data view is automatically applied when the data source is added to the report. Application administrators can have a user set default data view too! The published data view is available only to application administrators.
In order to define an administrator default data view, the application administrator must publish the data view and edit the Visual Analytics administration settings to set a default data view for the data source. The administrator default data view, unlike the user-set default data view, is automatically applied for all users who add the data source to the report. If there is a conflict, and the user has a user-defined default data view for the same data source, then the user default data view overrides the default data view set by an administrator.
Only an application administrator can publish a data view. A published data view becomes available for other users to apply. This is how you can share data views across users.
To manage a default data view for all users, you must be signed in as an application administrator. The data view that you want to set as default must also be published. From the Visual Analytics report, use the report menu to select Edit administration settings. Then click the Default Data View tab. From there you need to select the data source and then the desired data view. Remember, a default data view set by the user overrides the default data view set by the administrator.
Why use data views? They can quickly and easily provide Data pane settings to assist business users. Data views can also save you time from making repetitive calculated items, aggregated measures, and so on.
Here are some considerations to keep in mind: A data view is not intended to be a fully robust semantic layer, but it can help with some business logic. Also, data views are a point-in-time Data pane setting update. If you make a change to the data view, those changes are not pushed out to reports that have that data source with the data view applied. You cannot transfer a data view to a different data source, even though it might be similar.

=== Hierarchies 231 ===
A hierarchy is a defined arrangement of category data items based on a parent-child relationship. In many cases, the levels of the hierarchy are arranged with more general information at the top (Year) and more specific information at the bottom (Month).
You are able to mix data item types in a hierarchy definition. Hierarchies that consist of all geographic data items are considered geographic hierarchies and can be used in geo maps. Hierarchies enable you to add drill-down functionality to graphs and tables.
One of the most powerful features of Visual Analytics is that you can create hierarchies on the fly!
Here are three different objects that have a hierarchy data role assignment. We can see in the Crosstab object the Year -- Quarter -- Month levels. Notice how you can expand the different levels individually. The Crosstab object has additional navigation features like expand all, collapse all, and drill.
Next is the Bar chart object. There are breadcrumbs at the top to navigate back up the hierarchy, but you select the underlined values to move down in the hierarchy.
Last is the Geo bubble object. We won't cover how to create the geographic data items in this lesson, but when you create a hierarchy of all geographic data items, you can use the geographic objects. Double-clicking the bubble will drill down the hierarchy, and you use the breadcrumbs at the top to navigate back up the hierarchy.
To create a hierarchy, use the New data item menu and select Hierarchy. Then browse the available data items and move over the selected items by either double-clicking or using the center arrows. You can reorder the data items using the side arrows. The New Hierarchy window will generate a name based on the selected data items. If you edit the name, then the auto-naming feature will be disabled. When you click OK, the defined hierarchy will appear in the Data pane.
You can easily create a date or datetime hierarchy by right-clicking a date or date/time data item and selecting "New date hierarchy". You can see that the date hierarchy is created and added to the Data pane. If you right-click and edit the hierarchy, you can see the auto-generated levels and make any desired edits. The generated levels will depend on the granularity of the data item used to generate the date hierarchy.
Note that the auto-generated date or datetime data items are hidden by default. To make them visible, simply use the Data pane's overflow menu to unhide the desired data items.

=== Related Measures Outlier and Insights 308 ===
SAS Visual Analytics has many features to help you identify relationships in your data. The curve and point icon indicates that an item has related measures. This icon appears next to measures when a measure data item is selected and there is a strong degree of correlation (plus or minus 0.6 or higher). You must first select a data item. In this example, I selected Cylinders and we can see the hover over details for MPG (Highway). In this next example, I have selected Invoice, and I hover over Horsepower for the correlation details.
There are data thresholds for the related measures feature. If the data has fewer than 56 rows of data, then the correlation threshold increases to avoid the likelihood of random correlations. Also, if the data has more than 150 measures, then the related measures are not detected but can be configured in the SAS Environment Manager. You can also, as a personal setting, choose to disable the automatic correlation detection for the Data pane.
Outlier detection runs against all measures automatically to check for outlier values. The outlier detection icon (with four dots) indicates that an item has outlier values. The hover over displays general outlier information. You can also right-click and select View outlier details. === Bar Chart Objects 017 ===
SAS Visual Analytics has different types of bar charts that are useful for making comparisons. Bar chart objects are located in the Graphs group in the Objects pane and include bar charts, targeted bar charts, dot plots, needle plots, and butterfly charts.

=== Bar Charts 125 ===
Bar charts are useful for making general comparisons, presenting rankings, describing how parts relate to the whole, and showing questionnaire results. Bar charts display aggregated data for the distinct values of a category. They are probably one of the most versatile, and most used, graphs available. When using bar charts, it's a best practice to use a zero baseline. This is typically assumed and can lead to misinterpretation or tend to skew the understanding of the chart if a zero baseline is not used. A needle plot can be used to compare values to some baseline other than zero, or a dot plot could be used to highlight the difference between values that are close together.
NOTE: By default, a bar chart is sorted in descending order by the value of the first measure. For a grouped bar chart, the data is sorted by the category values in alphabetical order. Sort order can be changed by right-clicking the chart, selecting Sort, choosing the data item, and selecting Ascending or Descending.
Bar charts can contain groups, use lattice columns and rows, display animation, and support the hidden data role. Options are available for changing the direction, the spacing, and the transparency of the bars, specifying the grouping style (clustered or stacked) and the group scale (actual values or normalize groups to 100%), adding and modifying labels, and abbreviating numeric values.

=== Butterfly Charts 048 ===
Butterfly charts (also known as tornado charts) are useful for general comparisons, specifically for comparing two opposing groups (like loyalty and non-loyalty members, citizens and residents, or dogs and cats). It displays two sets of bars (one for each measure) with a shared category axis, where the baselines for the two bar charts are in the center of the chart and the ranges of the measure axes are identical. Depending on your data structure, you might need to create calculated data items that contain the measures for each group.
Butterfly charts support the hidden data role. Options are available for each group of bars and enable you to specify the baseline, change the spacing and the transparency of the bars, add and modify data labels and segment labels, and abbreviate numeric values.

=== Comparative Time Series Plots 117 ===
Comparative time series plots are useful for identifying anomalies in two separate time series. The comparative time series plot displays two time series in parallel with a shared horizontal time axis and separate vertical axes.
Comparative time series plots require a date or datetime data item for the Time axis and two measures (one for time series 1 and one for time series 2). Additionally, comparative time series plots can include data tip values and support the hidden data role. Options are available for each time series and enable you to specify the binning interval (Automatic, Fixed count, or Use format), the transparency of the line, the grouping style (Overlay unfilled, Overlay filled, or Stack filled), and the line thickness. Additional options are available for adding markers, abbreviating numeric values and adding and modifying data labels. For the binning interval, you can select Automatic (which enables Visual Analytics to automatically determine the best interval for the plot), Fixed count (which plots a number of equally spaced values determined by the value entered for Fixed bin count), and Use format (which will use the format of the date data item to specify the interval).

=== Crosstabs 515 ===
Another great object for learning about your data is the crosstab (also known as a crosstabulation table). This object is especially useful for viewing distinct values for category data items and summary information for your measures. Crosstabs often have two or more categories assigned to both the rows and columns, forming a matrix. The crosstab can also be helpful in spotting data quality issues and for gaining a broader insight into your data. Generally, crosstabs can be easier to read than list tables because they use less space, group values together, and can use hierarchies. When you use a crosstab, it's recommended that categories with lower cardinality (that is, categories with few distinct values) be placed in the Columns role and categories with higher cardinality (that is, categories with many distinct values) be placed in the Rows role. This enables users to quickly and easily read the table without a lot of scrolling.
Crosstabs accept columns (displayed at the top of the crosstab), rows (displayed on the left side of the crosstab), and measures (displayed as aggregated values in the cell). Options are available for adding and modifying borders, using abbreviated numerical values for each measure column, applying the indented layout (which displays subtotals for each group), modifying the color and format for row headings and column headings, specifying the placement, color, and format for measure headings, showing missing labels as blanks, and fitting columns to the width of the crosstab based on the space available.
For cells, additional options are available for adding horizontal and vertical lines, including row numbers, providing an optional customized heading, restarting row numbers for each group, condensing the row height to remove extra white space in rows, and modifying the background color and alternating the background color of the cells.
When working with crosstabs, you might want to resize columns, rearrange columns and rows, sort by categories or measures, and create and add hierarchies or calculations. You can resize columns to improve the readability of the data by ensuring that data values are not cut off and by reducing the amount of white space. To resize columns, click on the edge of a column heading and drag to the left or right to resize.
You can rearrange columns to more easily view related data items. To rearrange columns, you can use the Roles pane to drag the column to a new position in the list of columns.
You can sort by measures or categories in a crosstab to display the values in a logical order. By default, the crosstab is sorted in ascending order by the categories. You can modify the sort by right-clicking the crosstab heading, selecting Sort, and selecting the data item and order of the sort. Alternatively, you can click another column heading in the table to change the sort. Clicking once sorts by that column in ascending order, and clicking twice sorts by the column in descending order.
When two or more category data items are assigned to the Columns or Rows roles, you can create and add a hierarchy from the crosstab. This enables you to expand and drill down to view different levels of the hierarchy. To create and add a hierarchy, right-click a category heading and select Create and add hierarchy to rows or Create and add hierarchy to columns.
A new hierarchy is created (using the names of data items in that role), is added to the Data pane (for use in other graphs) and is assigned to the roles of the crosstab. When a hierarchy is added to a crosstab, you can expand a single level by clicking the Expand button. Alternatively, you can drill down to view more details about that level by clicking the data item. When you are drilled down into a hierarchy, a ribbon that indicates the current position is displayed at the top of the crosstab and can be used to navigate between levels.
You can create derived data items (percent of totals and percent of subtotals) for measure data items assigned to the crosstab. These derived data items enable you to compare values between and across groups and can be used only with crosstabs. Percent of column total displays the percentage that each cell contributes to the column total, and Percent of row total displays the percentage that each cell contributes to the row total. In this example, Percent of column total for Product Sale displays how much each country contributes to the total for all countries. This means that the percentages add up to 100% for the column.
Percent of column subtotal displays the percentage that each cell contributes to the column group, and Percent of row subtotal displays the percentage that each cell contributes to the row group. In this example, Percent of column subtotal for Product Sale displays how much each country contributes to the total for each continent. This means that the percentages add up to 100% for each continent.
To create a derived data item, right-click the measure column in the crosstab and select Create and add calculation. Options are available for naming the derived data item and for selecting the type of data item. The types available depend on the data items assigned to the Columns and Rows roles.

=== Data Roles 308 ===
Many objects have similar roles: some roles are required, and others are optional. Many roles are standard, but some roles have special uses, like the Lattice rows and Lattice columns roles, the Data tip values role, the Animation role, and the Hidden role.
A lattice is a multi-cell graph in which the plot in each cell represents a specific crossing of values. In Visual Analytics, you can create a multi-cell graph by assigning data to the Lattice rows and the Lattice columns roles. In this example, Order Type is assigned to the Lattice columns role, so one column appears for each order type. Loyalty Member is assigned to the Lattice rows role, so one row appears for each type of loyalty member. This role is useful for comparing data across multiple groups.
A data tip displays details about an element. In Visual Analytics, you can add additional details about an element by assigning data items to the Data tip values role. By default, all data items assigned to other roles will be added to the Data tip values role. In this example, two data items (Average Efficiency and Number of Facilities) are assigned to the Data tip values role, so the aggregated values for those data items appear when the user places the mouse pointer over a bar. This role is great for providing additional information to the report viewer without having to assign the data to the object itself.
Data items assigned to this role can be categories, dates, measures, aggregated measures, or some combination of these. A category data item should be assigned to the Data tip values role only if doing so will not increase the number of rows in the query. For example, suppose I have a bar chart that shows profit by Continent. You can change the order in which data items appear in the data tip by reordering the data items on the Data Roles pane.
Animation enables you to view changes in data over time. In Visual Analytics, you can animate a chart by assigning a date data item to the Animation role. In this example, Transaction Month is assigned to the Animation role. When a data item is added to this role, a toolbar appears at the bottom of the chart that enables you to play the animation and the date value is displayed in the graph by default. Multiple options can be modified to control the appearance of the animation values. When using animations, be sure to focus on changes that are different from the norm.
The Hidden role enables you to include a data item in query results when you want to use the values, but you don't want to display the data in the chart. Data items assigned to this role are available for color-mapped values, external links, and mapping data sources.
A data item should be assigned to the Hidden role only if doing so will not increase the number of rows in the query. The Hidden role is not available for all objects and is not intended for column-level security purposes. You cannot assign a data item to the Hidden role and the Data tip values role at the same time.

=== Dot Plots 051 ===
Dot plots are useful for general comparisons. Dot plots display data for each value of a category data item using dots. The position of each dot on the response axis represents the summarized value of the measure. Because dot plots often use a nonzero baseline, it's easier to highlight differences when values are close together.
Dot plots minimize the amount of chartjunk displayed. Chartjunk is any visual elements in graphs that are not necessary to understand the graph or that distract from the main message of the graph. Dot plots are often preferred over bar charts because bar charts can distort the values if the area of the bars is compared and not the height.
Dot plots can use lattice columns and rows and support the hidden data role. Options are available for changing the transparency, the size, and the fill of the markers.

=== General Options Layout 041 ===
The last general option is Layout. Layout options include width and height.
Both the width and height of the object are expressed as a percentage of the space on the canvas or inside a container. By default, SAS Visual Analytics automatically computes the height and width of any control or text object when the report is rendered to increase portability across various screen sizes. For these objects, you should specify a fixed height and width only if you want the object to use that specified size on any screen. In addition, you can choose to extend the height and width if space is available or shrink the height and width of an object if there isn't sufficient space.

=== General Options Object 304 ===
All objects have general options (like Object, Style, and Layout).

The Name option enables you to specify a name for the object. This name is used to identify the object in the Outline pane, in the drop-down list at the top of the right pane, and in the Actions pane. All names in a report must be unique.

The Periodically reload object data option enables users to specify the interval in which an object's data should be refreshed. You can specify the refresh interval in seconds or minutes. === General Options Style 404 ===
Now let's look at the Style options.
Style options include Font, Background, Border, Padding, Internal padding, Data Skin, Fill, Line/Marker, Gradient, Missing, Data Tip Style, and Data Tip Background. These options available are context sensitive. That is, they depend on the selected object.
The Font option specifies the font used for all text in the object. This includes axis labels, tick values, data labels, and data tip values. It's a best practice to use consistent fonts in your reports, so it's recommended to choose a font at the report level and not modify the fonts for individual objects.
The Background option enables you to specify the color and transparency of the background for the object. Because you should not overuse colors in your report, it's recommended to use a neutral color (like white) and modify the background color only in special circumstances.
The Border option adds a border around the object and enables you to specify the thickness and transparency of the border. Borders are typically considered chartjunk, a visual element in a graph that is not necessary to comprehend the data presented in the graph. To increase the comprehension and improve the effectiveness of your report, borders should be avoided.
The Padding option specifies the amount of empty space to include around the outside of the object. Margins and padding can be used to add negative space to your report, which can increase the impact of your report. However, be aware that too much padding can crowd report content, especially when users view the report on small screens or set the zoom level above 100%. If you modify padding from the default, test the report thoroughly to ensure that the content is displayed nicely on all screen sizes. For objects that contain multiple visuals (like the Automated explanation, Automated prediction, and Text topics objects), the Internal padding option specifies the amount of empty space to display between those visuals.
The Fill option specifies the order in which colors are assigned to fills for each unique group in the chart. For example, a bar chart with three groups will use the first color (blue) for the first group, the second color (yellow) for the second group, the third color (purple) for the third group, and so on. If there is no data item in the Group role, then only the first color is applied to the graph.
To change a specific color, select that color and choose a different option. Choose complementary colors as they are pleasing to the eye when used side by side and help improve accessibility, especially for users who are color blind. The default palette choices in Visual Analytics cycle through warm and cool colors for this purpose.
The Line/Marker option specifies the order in which colors are assigned to lines and markers for each unique group in the chart. If your chart contains both fills and lines, it's recommended to choose a similar color for each group. The default palette choices in Visual Analytics use similar colors for fills and lines.
The Gradient option specifies the colors that make up the color gradients in the chart. When working with gradients, be aware that three-color gradients are generally not accessible to people with color-deficient vision. Instead, choose colors with a sufficient difference in luminosity.
The Missing option specifies a color that represents missing values in a data item assigned to the group role.
The Data skin option specifies the visual style of the data elements in the object. You can choose the default, none, pressed, sheen, crisp, gloss, matte, or flat. It's a best practice to choose only one data skin per report and apply it to all objects for consistency.
The Data tip style option enables you to specify the font size and color of the text in data tips and the Data tip background option enables you to select the color of the background of data tips. Remember, as a best practice, all text should use consistent fonts and sizing, and you should not overuse colors.

=== Graph Options Animated Graphs 154 ===
For animated graphs, additional options are available for controlling the animation value displayed in the chart. Animation options include Animation date or time value, Placement, Order, Text Size, Text Style, Transparency, Contrast option, and Fill color. When using animations in graphs, be sure to focus on changes that are different from the norm.
The Animation date or time value option, when selected, displays the date or time value for the time period displayed in the chart. When the animation is playing, this value is constantly updated.
The Placement option specifies the position of the animation value in the chart. The animation can be placed in the upper, middle, or bottom left, the upper, middle, or bottom center, or the upper, middle, or bottom right. It's a best practice to place the animation value where it will not overlap with data elements. This position can depend on the data in the graph.
The Order option specifies whether the animation value is displayed in front of data elements or behind data elements. The Text Size option enables you to modify the size of the animation value as a percentage of the height of the object. The Text Style option enables you to change the style (bold or italicized) and color of the animation value. The Transparency option enables you to change the transparency of the animation value. The Contrast option enables you to specify whether the animation value appears with a colored background (Box) or without one (None).
If you choose to display a colored background for the animation value, the Fill color option enables you to choose the color of that background. Because you should not overuse colors in your report, it's recommended to use a neutral color (like white) and modify the background color only in special circumstances.

=== Graph Options Axis 251 ===
Most graph objects have axis options (like X Axis Options and Y Axis Options) and graph options (like Graph Frame, Reference Lines, Legend, and Data Options).
Axis options are the same for the x and y axes and include Rotate value label, Overview axis, Fixed minimum, Fixed maximum, Logarithmic scale, Axis label, Axis line, and Tick values. The options available are context sensitive. That is, they depend on the selected object.
The Rotate value label option enables you to display category tick values at an angle, so more labels are shown. This option has no effect if a lattice is used in the graph.
The Overview axis option enables you to add an overview axis to the chart. The overview axis is a scrolling axis that can be modified to control how much of the axis appears in the main view and which segment of the axis appears. This option has no effect if a lattice is used in the graph. Because overview axes are not accessible, you should avoid adding these to your reports.
The Fixed minimum and Fixed maximum options enable you to specify a fixed range for the axis. Fixed axis ranges can be useful for accessibility, because they enable users of sonification to understand the scale of data shown in the object. This is especially useful when the values shown in the object can change due to filtering or drilling down in a hierarchy. However, if your data updates frequently or is likely to fall outside the fixed range when filtering or drilling, a fixed axis range is not recommended as values can unknowingly fall outside the fixed range.
The Logarithmic scale option enables you to specify that the axis uses a logarithmic scale. This is especially useful for viewing relationships when your data has outliers where the largest numbers in the data are hundreds or even thousands of times larger than the smallest number. === Thresholds for Report Objects 218 ===
Each report object has a threshold for how much data it can visually display. Many report objects will not display high-cardinality data items with many unique values. For more information about the default client-side thresholds for report objects, see "High-Cardinality Thresholds for Objects" in the SAS Visual Analytics Reference documentation. These client-side thresholds are controlled by the maxRowsLookup properties for the sas.reportdata.properties service.
A client-side threshold is the amount of data that CAS will send in the response to the client--in this case, Visual Analytics.
When you create an object in Visual Analytics, the client will send a request to CAS. CAS, similar to a data warehouse, contains all the data. The analytic engines summarize the data based on the object, the roles assigned, and any filters or ranks applied. After summarization is complete, the analytic engines limit the number of aggregated rows based on the object's client-side threshold and sends the aggregated result back to the client.
Let's consider an example. Suppose you would like to display a list of all your customers in a table. You have 68,300 customers, but the default client-side threshold for list tables is 40,000 rows. This means that the list table will display only 40,000 rows. If a total is included, this row counts as one of the 40,000.
To see all customers, you can modify the Override system data limit option to 70,000. In this case, all customers will be displayed in the list table.
Notice that even when the list table truncates the rows due to the client-side threshold, the totals are still accurate and based on all the data.
An administrator can edit the configuration properties for an existing object or create a new configuration if one is not listed for the object by default. Modifying these configuration properties will impact all instances of the object in the environment and can directly impact performance. Before making changes, ensure that the changes are necessary and that they will not adversely impact your environment. For more information about the configuration properties, see "Configuration Properties for SAS Visual Analytics" in the SAS Visual Analytics: Reference documentation.

=== Calculated Data Items vs Aggregated Measure 748 ===
Recall the available types of calculated items we can create in Visual Analytics. Creating hierarchies and custom categories were covered in the Refining Data for Effective Reports lesson. Geographic topics will be covered in the Working with Impactful Objects lesson and Parameters will be covered in the SAS Visual Analytics 2 course.
This lesson will cover calculated data items like date time, category, and measures and aggregated measures.
In general, the term "calculated data item" means that it is a new data item created from existing data by using an expression.
For a calculated data item, the expression is evaluated for each row of unaggregated data. That means the expression will be evaluated for each observation in the source data before aggregations are performed. A calculated data item uses default aggregation behavior and the expression accepts parameters.
For an aggregated measure, the expression is evaluated on aggregated data. Aggregations are evaluated by context and that is determined by the object's Role assignments. There are two contexts that can be used when defining an aggregated measure expression: By Group -- which calculates the aggregation for each subset of the data item, or For All -- which calculates aggregation for the entire data item (after filtering). The aggregation behavior is defined by the expression, hence its name, aggregated measure. Some, leaning toward most, of the aggregated operators accept parameters.
Let's look at a calculated data item. Calculated data items are created by performing mathematical calculations on numeric values, such as Profit equals Revenue minus Expenses, or by performing operations on date/datetime data items or categories, such as Age equals Today minus the Date of Birth or a Full Name equals the First Name concatenated with the Last Name.
For example, you can create a new calculated data item (Target Profit) by multiplying Profit and Increase. For each row in the data source, the operation is evaluated, and the new data item is created. Then, when that data item is used in a graph (for example, with Product Line), the values for Target Profit are totaled for each Product Line.
Now let's look at the aggregated measure. The first step is to aggregate the values and then perform the operations. The aggregation context changes depending on the object's data role assignments. For example, the Percent of Total expression requires to first sum the data values by group, then sum all of the data values, and then take the ratio of those two sums.
Another example is for a periodic operation, which means over the span of a time group. In this example, Difference from Previous Period, the aggregated measure, will first find the data values of CurrentYear and take the Sum, then find the data values of PreviousYear and take the sum, and then take the difference of those two sums.
For each aggregation you use in your expression, you must define an aggregation context.
As a reminder from our Percent of Total example, notice that the numerator uses Sum (ByGroup) and the denominator uses Sum (ForAll).
For example, you can create a new aggregated measure (Profit (Percent of total)) by dividing the sum of the profit for each group by the sum of the profit for all groups. In this instance, because Profit (Percent of total) is paired with Product Line, Profit is first totaled for each product line, and then Profit is totaled for all.
Then, the operation is evaluated for each Product Line to show the contribution to total profit.
You could take the same aggregated measure and pair it with Region to see the contribution of each region to total profit. The dynamic nature of aggregated measures makes them extremely useful for analysis and reporting.
Now let's see how we build these expressions in Visual Analytics using the Expression Editor. To open the Expression Editor, use the New data item menu and select Calculated item. There is a single user interface to build either a calculated data item or aggregated measure. Then, you can use the buttons to build your expression, or freeform type. You can use the filter at the top to subset the list, and hovering over will provide a summary of the operator or function. When you make a selection, operators and functions will open in the Expression Editor Side Pane. This gives you additional drop-down menus to help build your expression, and additional details about the expected variables.
If you prefer freeform typing, you can use the built-in syntax help to build your expression. It will suggest functions and data items as you type. Use the arrow keys on your computer to navigate the offered suggestions, and the ENTER or TAB key to select a suggestion. Depending on your screen size a description of the function and sample syntax will display or you can click on the arrow to expand. If you freeform type the name of the data item with a space in its name, ensure you enclose it in a name literal. To do this, put the data item name within single quotes with an n after the closing quote. You can also see additional data item properties.
When you click on a function, you can use the side pane to easily navigate to nested subexpressions inside of the selected function.
To point out some more enhanced coding features, you can create parameters on the fly. You can also add comments to your expression using standard SAS syntax. At the bottom, click to display error messages to help debug the expression.
You can right-click inside the editor to format your code to make it more readable or to use the command palette. The command palette allows you to find and replace, highlight all occurrences of an expression, change the code font size, and much more!
Also notice that when you are building a calculated data item expression, you will see a Results Preview window. This is not available for aggregated measure expressions as the expression cannot be evaluated until assigned to an object.
I mentioned earlier that we have a single user interface to define both calculated data items and aggregated measures. Here we can see their definitions side by side. Can you spot any differences? Notice that the Calculated Data Item expression has no aggregation functions, the result type is determined by the expression, we have a results preview, and there is no scoped expression definition.
For the Aggregated Measure expression, it must contain an aggregation function and context type. Its result type is always an aggregated measure, there are no results to preview, and you can see that there is a scope definition option. A scoped aggregated measure is when you can define multiple expressions for a single aggregated measure that changes depending on the intersection of data roles. A scoped aggregated measure is covered in more detail in the Visual Analytics 2 course.
Here's a look at the available operators and functions available to you in the Expression Editor. When creating complex aggregated measures, you might run into an error that tells you that you cannot have nested aggregations. This means that you might need to perform your calculation in a multi-step process. This is covered in greater detail in the Visual Analytics 2 course in which you make use of an aggregated data source and aggregated measures.
Periodic operators are a special set of operators that aggregate data over a period of time. Typically, the interval data item requires the format to include the year. For example, if you were looking at weeks, every year has zero to 52 weeks in a year, and the only way to differentiate them is to include year. That is how this example is able to calculate Profit (Difference from previous period). Notice that the first row is missing. That is because the previous period's data is not available and it cannot be calculated.

=== Gauges 314 ===
Gauges, or dashboard indicators, are useful for measuring progress toward a goal, monitoring key performance indicators, comparing performance across groups, and tracking performance over time.
Due to their simplicity in reading and understanding, gauges are great for representing data that needs immediate attention or action. A bullet gauge is useful for comparing forecasts to actual values and often begins at zero. A speedometer gauge imitates the design of a speedometer on a vehicle and is useful for showing ratings (like for surveys) and are often normalized to 100%. This ensures that the ranges are consistent across multiple gauges and makes for easier comparison. Be aware that speedometers take up a lot of space and it can be hard for users to compare multiple gauges.
A thermometer gauge is useful for showing progress toward a goal for fundraising. A progress indicator can easily display the utilization of a resource (like the occupancy of a hotel or inventory levels).
In Visual Analytics, many shapes and styles of gauges are available. Here you can see all variations of arc and dial shapes and all the styles of gauges you can create. To create a traditional speedometer gauge, use the dial shape and the speedometer style.
Here you can see all variations of linear shapes and all the styles of gauges you can create. To create a traditional bullet gauge, use the horizontal linear shape and the bullet style. To create a traditional thermometer gauge, use the vertical linear shape and the thermometer style. To create a traditional progress indicator gauge, use the vertical linear shape and the progress indicator style.
In addition to assigning data to roles for the gauge, you must also define a display rule. A display rule is added automatically to the gauge. By default, the display rule contains three intervals and a default range (from about 40% to 160% of the aggregated measure value). If the measure is a percentage (like customer satisfaction or product quality), the starting range begins at 0%. It's a best practice to define intervals based on your business objectives and adjust goals as circumstances change.
Gauges can display targets, can contain groups, and support the hidden data role. Options are available for changing the shape (Arc, Dial, Half dial, Full dial, Horizontal linear, or Vertical linear), the style (Bullet, Speedometer, Thermometer, Progress indicator, Active range only, or Custom), and for specifying what type and how data labels are displayed. For labels, you can choose to show the value label (for the measure), the range labels (for the display rule), or the target label (for the target).
For custom gauges, additional options are available for choosing the type of indicator (Needle, Bar, or Bar needle), for specifying the ratio of the range on the gauge, for displaying the active color only, and for specifying the placement of the range (inside or outside).
For groups, additional options are available for specifying the lattice cell limit, the row limit, the column limit, and the lattice layout.

=== Geography Data Items 205 ===

=== Point Maps 333 ===
Maps that use points are useful for pinpointing exact locations. Point maps are located in the Geo Maps group in the Objects pane and include geo bubble maps, geo coordinate maps, and geo pie maps.
Geo bubble maps display your data as a bubble plot, where each bubble is located at the center of a geographic region or at the coordinate of a location. Geo bubble maps are useful when data is not evenly distributed. This is because the bubble plot can compare two measures. One is used for the size of the bubble, and one is used for the color of the bubble. Another advantage of a bubble plot is that the bubble size helps with comparing regions without the area of the region itself causing distortions. Sometimes, however, bubbles can overlap with other bubbles, making the chart difficult to read.
Geo bubble maps require a geography data item and a measure to specify the size of the bubble. In addition, geo bubble maps can use an additional measure to color the bubble, display data tip values, display labels for each bubble, display animation, and support the hidden data role.
Options are available for thinning data labels, changing the transparency of the bubbles, specifying the range for bubble sizes, and adding and modifying data labels.
Geo coordinate maps (also known as dot distribution maps or dot density maps) display a map with a scatter plot of coordinates where each marker is located at the center of a geographic region or at the coordinate of a location. Geo coordinate maps are useful for detecting spatial patterns and understanding the distribution of data over a geographic region. Geo coordinate maps should be used only when there is an even distribution of values within each region.
Geo coordinate maps require a geography data item and can use two additional measures: one to size the coordinate and one to color the coordinate. In addition, geo coordinate maps can display data tip values, display labels for each coordinate, display animation, and support the hidden data role.
Options are available for thinning data labels, changing the transparency of the coordinates, modifying the markers (size, shape, and fill), and adding and modifying data labels.
Geo pie maps display a map with pie charts located at the center of a geographic region or at the coordinate of a location. Geo pie maps are useful if you want to see the distribution of values among a few groups for a specific geographic area. Geo pie charts have the same issues as regular pie charts, but on a larger scale. Recall that for pie charts, it is very hard to compare the relative sizes of the slices in the chart and changes over time are difficult to detect. For these reasons, you should use geo pie charts sparingly.
Geo pie charts require a geography data item, a measure to size the slices, and a category to create the slices. In addition, geo pie charts can use an additional measure to size the pie chart, display data tip values, display labels for each pie chart, display animation, and support the hidden data role.
Options are available for thinning data labels, changing the chart style (pie or donut), changing the transparency of the pie charts, sizing the chart, specifying the starting point for each pie chart and the direction in which the slices are drawn, displaying the "Other" slice and the minimum percentage for values to be grouped into "Other" and adding and modifying data labels.

=== Polygon Maps 449 ===
Maps that use polygons are useful for comparing regions. Polygon maps are located in the Geo Maps group in the Objects pane and include geo cluster maps, geo contour maps, geo region maps, and geo region-coordinate maps.
Geo cluster maps display your data as a clustered scatter plot, where markers that are in close proximity to each other are clustered into a single marker. A number on the marker indicates the number of points represented by that cluster. Geo cluster maps are useful when you want to group locations in nearby areas for different zoom levels. As you zoom or pan in the geo map, the clustering is reevaluated. Because the data is grouped, clusters are not affected by display rules.
Geo cluster maps require a geography data item and can use two additional measures: one to size the bubble and one to color the bubble. In addition, geo cluster maps can display data tip values, display labels for each cluster, and support the hidden data role.
Options are available for thinning data labels, coloring clusters by value, specifying the maximum number of clusters, modifying the cluster spacing, changing the transparency of the clusters, formatting the markers (the size, the shape, and the fill), and adding and modifying data labels.
Geo contour maps display shaded areas that represent a three-dimensional shape on a two-dimensional map. Geo contour maps are best used to show very dense data (like population or elevation). Areas that display the same amount of data are shown on the same contour level, while the spacing between contour lines indicates differences between the locations (where closer lines indicate larger differences and widely spaced lines indicate smaller differences).
Geo contour maps require a geography data item and a measure to color the area.
Options are available for changing the transparency of the contour levels, specifying the base contour (those areas where information is not known), modifying the fill of the contour levels, specifying the number of levels, displaying or hiding contour lines, changing the bin count used to create the contour levels, and adding and modifying data labels.
Geo region maps (also known as choropleth maps) use colors to show variations by location. With region maps, larger regions seem more emphasized than smaller ones, which can skew your analysis. Geo region maps should be used only when there is an even distribution of values within each region. Be aware that a geo region map cannot be used to display zip code information (unless you define a geographic data provider with the boundaries for each zip code) or any geographic data that was created using latitude and longitude in data.
Geo region maps require a geography data item and a measure to color the area. In addition, geo region maps can display data tip values, display labels for each region, include data values for each region, display animation, and support the hidden data role.
Options are available for changing the transparency of the regions abbreviating numeric values, adding and modifying data labels and adding data values and displaying placeholders for regions not in the data.
Geo region-coordinate maps enable you to display both colored regions and coordinates. This type of map is great for comparing two levels of data. The region colors represent more general information (like states), and the coordinates represent more specific information (like customer locations).

=== Actions 036 ===
Actions, like prompts, can make your reports more versatile by enabling viewers to access
    the information that's important to them.
    Actions are used to direct a report viewer's attention to specific results in a report.
    Two types of actions can be added to a page.
    Automatic actions that can be added between all objects at the page level and manual actions
    that can be added between specific objects on a page.
    Each page can either have manual actions or automatic actions, but not both.
    If the objects use different data sources, you need to specify a data source mapping
    for the actions to work.

=== Automatic Actions 101 ===
Automatic actions can be added between all objects on a single page.
    Three types of automatic actions are available,
    linked selection, one-way filter, and two-way filter.
    Using automatic actions enables viewers to tailor their experience
    by specifying the order in which their actions are applied,
    making the report more dynamic and valuable.
    In addition, automatic actions can speed up development time
    by enabling users to create reports quickly and easily.



    Automatic actions work only on objects that use the same data sourced
    or on objects that have sufficient data source mappings.
    Automatic actions are available only for objects
    that support linked selection or filter actions.
    In Visual Analytics, a setting, action mode for new pages,
    enables you to specify whether new pages use manual actions,
    default, or one of the automatic actions.
    As a best practice, you should finalize the report layout
    before enabling automatic actions.

=== Automatic Actions Linked Selection 116 ===
The automatic link selection action highlights related data in multiple objects.
    The data has the same appearance in each object, which makes it easy for report viewers to
    determine the relationship between the data.
    When automatic link selection actions are added to a page, all objects on the page have
    linked selection actions between them.
    In this example, the page contains four objectsâ€”a bubble plot, a tree map, a crosstab, and a
    bar chart.
    If the viewer selects a bubble in the bubble plot, the same data in the other objects is
    highlighted.



    Linked selection actions can be applied in any order, so if another viewer were to select
    a bar in the bar chart, the same data would be highlighted in the other objects.
    Notice that when another object is selected, the previous selection is removed and related
    data is highlighted in the other objects.



    When you drill down on a hierarchy and link selection automatic actions are enabled, the
    drill down propagates its selection to other objects on the page.
    However, the other objects are not displayed in an expanded state.
    Because screen readers cannot perceive elements that are highlighted with a linked selection
    action, for accessibility reasons, it's recommended that you avoid using these actions.

=== Automatic Actions One-Way Filters 110 ===
The automatic one-way filter action enables viewers to apply filters between objects in any order.
  The filters are applied in the order in which the data is selected on the page.
  This enables viewers to filter the data however they like without the designer having to account for every possible filtering scenario.
  
Typically, the automatic one-way filter action is used for objects that are hierarchical or cascading.
  In this example, the page contains four objects, a bubble plot, a tree map, a crosstab, and a bar chart.
  If the viewer selects a bubble in the bubble plot, the other objects on the page, the tree map, the crosstab, and the bar chart are filtered.
  Then, if the viewer selects a bar in the bar chart, the remaining objects on the page, the tree map, and the crosstab are filtered.
  Lastly, if the viewer selects a tile in the tree map, the last object on the page, the crosstab, is filtered. 

    When a selection in any chart is modified, all downstream filter selections are removed.
    By default, three-page templates, dashboard, panel, and stack have automatic one-way filter actions defined.

=== Automatic Actions Two-Way Filters 112 ===
The automatic two-way filter action enables viewers to apply filters between all objects on a page, even previously selected objects.
    This enables viewers to see the impact of filters on previously filtered objects as well.
    In this example, the page contains four objects, a button bar, a list control, a list table, and a bar chart.
    If the viewer selects a button on the button bar, the other objects on the page, the list control, the list table, and the bar chart are filtered.
    Then, if the viewer selects an item in the list control, all the objects on the page, including the previously selected object, the button bar, are filtered.
    Lastly, if the viewer selects a bar on the bar chart, all the objects on the page, including the previously selected objects, the button bar, and the list control, are filtered.



    For two-way automatic filters, deleting a filter token does not impact the other filters because there is no chain of filters.
    It's recommended that you not use required prompts with automatic two-way filters.
    If a prompt is required and two-way automatic filters are enabled, it's possible to get stuck in a single value selection for a prompt.

=== Filter Data 525 ===
In Visual Analytics, you use filters to subset your data. There are filters available at both the report and object level. Filters are saved with the report and can be used to focus on anomalies or inconsistencies that are discovered during analysis.
Recall from earlier that we have two groups of filters. Dynamic filters, which are covered in the "Designing Interactive Reports" lesson of this course, are filters that can be modified or used by the report viewer. The second group is static filters, which we cover in this section. These static filters must be defined and applied by the report designer.
Static filters can be split between those that are applied at a report level and those that are applied at an object level.
A data source filter is a global filter that subsets data for the entire report. This filter is applied to every object that uses the data source. It acts as a pre-filter by filtering the data before it is brought into Visual Analytics. This can be seen in the updated cardinality values in the Data pane after the filter is applied.
Basic and advanced filters are object-level filters, and they subset data for individual report objects. The basic report filter subsets the object using a single data item expression, whereas the advanced report filter subsets the object using a complex expression that can contain any number of data items and operators.
A post-aggregate report filter is an object-level filter that subsets the report object using aggregated values, not individual values. These aggregated values are evaluated in the report object and are used to specify the minimum and maximum values in the selectable range.
A common filter can be a basic, advanced, or post-aggregate filter that is shared between objects. It is available across the report and can be applied to any objects using the data source.
Data source filters are used to restrict the data that is displayed in the report. To apply a data source filter, use the Data source menu and select Apply data filter. Then use the Expression Editor to define a Boolean expression to evaluate whether those rows will be returned. There is a limit of one data source filter per data source, so you might need to build a complex expression to include all the data items that you require. Verify that you are getting the expected number of returned observations for your evaluated expression.
You can use the buttons to build your expression, or you can add items freeform. You can use the filter at the top to subset the list, and hovering provides a summary of the operator or function.  When you select a function, it is displayed in the Expression Editor side pane on the right. This gives you additional drop-down menus to help build your expression, as well as additional details about the expected variables. The Results preview displays the columns used in the expression and how the filter expression is evaluated. This can be extremely useful when debugging. 
Here we see the results of an applied data source filter. Notice the Data pane cardinalities before the data source filter is applied and after. The data source filter is applied to every object in the report that uses the data source. A report with multiple data sources can have multiple data source filters, but there is a limit of one data source filter per data source. The data source filter can be a complex Boolean expression.
A basic filter is a filter that includes only one data item in the filter expression and usually uses the Filters pane to click through the steps. First you must click the object that you want to apply the filter to. Then be sure you have the Filters pane open. Third, use the New filter menu and select the data item for which you want to create a filter. Next, select the data values that you want to include. Depending on whether the data item is a measure or a category, you are presented with either continuous or discrete value options. You can use the toolbar for more filter options.
To apply an advanced filter, you again first select the object for which you want to create a filter. Then make sure you have the Filters pane open. Then use the New filter menu and select Advanced filter. Now you can use the Expression Editor to build the complex Boolean expression filter. You can use the returned observations to verify that your filter expression returns the expected results. You will be able to see the applied filter expression in the Filters pane when you have the object selected.
To apply a post-aggregate filter, you of course need to have the object selected and the Filters pane open. Then you need to select the measure data item, and you initially see the detail data values available for a basic filter. If the object that you have selected supports filtering on aggregated values, then select the Filter aggregated values option. Notice that the range of values updates to display the aggregated data values now. Look to the right of the data item name. The type of aggregation being used is listed in parentheses. By default, the aggregation type assigned to the data item is used. In this example, Product Sale is using the sum aggregation, but it would show if the data item was using average, min, max, and so on. Use the toolbar to select additional filter options. For example, you could change the condition type to include endpoints.

=== Viya CAS and Visual Analytics 355 ===
We have seen how we can quickly get started using SAS Visual Analytics. Now let's take a look at the high-level architecture of SAS Viya and CAS. We'll give a quick overview of single versus multi-threaded processing. And finally we'll see how Visual Analytics is a CAS client which means we'll look at how Visual Analytics requests and receives responses from CAS.
CAS stands for the Cloud Analytic Services and is SAS's latest and most powerful analytic engine. It is pronounced like 'SAS' not 'jazz'. CAS has a unique proprietary data architecture which is a combination of resident memory, virtual memory, and permanent, on-disk storage. As you can see in the high-level architecture diagram, CAS is the analytic engine for SAS Viya but there are other supporting services. There are stateful services, stateless services, and other services that support the infrastructure of SAS Viya.
CAS is designed for multi-threaded processing, even in single machine architectures. In a CAS single machine deployment, the CAS Controller and CAS Worker are the same server. In a CAS multi-machine deployment, there is the CAS Controller and then one or more CAS Workers. As client requests come in for analytic responses, the CAS Controller sends the requests down to the appropriate workers and then aggregates the results before responding to the client.
Let's take a look at SAS Visual Analytics using CAS. Here we can see that Visual Analytics is referred to as a client. Any web application making a request of CAS is called a client.
When you create an object in Visual Analytics, the client will send a request to CAS. CAS, similar to a data warehouse, contains all the data. The Controller then instructs the CAS Workers and their analytic engines to perform the requested operations on the data that is available to them. The CAS Workers then send their results back to the CAS Controller for final aggregation and to apply any post processing actions, such as rank. Then the CAS Controller sends the results back to the client. The results are structured data only, not tables or charts.
What is a Visual Analytics report? Here we can see a browser rendered Visual Analytics report. We can see images, text, key values, a time series chart and a date slider prompt. Under the covers though, the structure of a Visual Analytics report is called the BIRD which stands for the Business Intelligence Report Definition. Here is a screenshot of the XML structure but you could also view it in JSON. This is the "recipe" or "map" that the browser uses to render the graphics of the report. The returned CAS results are embedded within the BIRD.
Here is the Visual Analytics request for one of the key value objects. CAS requests can be in the form of CASL, which is the CAS Language, or in the form of CAS Actions. In this example, we can see that a CAS Action of simple summary is being requested for this key value object. It will pass all of the information to CAS to complete the request such as CAS Library name, table name, data items, aggregation type, etc. This is done for every object in the report. The request will also include any filters configured for the report object.
Here is an example CAS response. Remember, CAS only returns structured data that the client will render into a graphic. === Box Plots 249 ===
Box plots are useful for viewing information about the variability and extreme values of a measure between groups. Box plots are especially useful for showing survey or questionnaire results, because you can see the average response and the range of responses for various answer choices. Box plots can also be used to assess the normality of multiple measures. In a perfectly normal distribution, the mean and median will be the same.
In a box plot, the size and location of the box indicate the range of values between the 25th and 75th percentile (interquartile range, IQR) for that group. The diamond marker indicates the mean value, and the line inside the box indicates the median value. You can also modify the options to display outliers in the plot. Outliers are data points whose distances from the interquartile range are more than 1.5 times the size of the interquartile range. Outliers can be located at the upper extreme or the lower extreme of the data range, or both. The whiskers (lines protruding from the box) can indicate either the minimum and maximum values or the range of values that are outside the interquartile range but close enough to not be considered outliers. If there are many outliers, the range of values is shown as a bar that is colored to represent the number of values within that range (as seen here).
The data tip for each box displays descriptive statistics for that group, like the minimum, maximum, lower whisker, upper whisker, first quartile, third quartile, average, median, standard deviation, and count. The data tip for each outlier bin displays additional information about the outliers, like the range of the bin and the frequency of observations falling within that bin.
Box plots require at least one measure, accept a category, and can use lattice columns and rows. Options are available for changing the direction of the boxes, modifying the measure layout (Automatic, Separate axes, Shared axis), and specifying how outliers are displayed. Outliers can be ignored (so they are excluded from the plot), shown (so they are shown separately from the whiskers), or hidden (so they are included within the whiskers). Additional options are available for drawing outlines around outlier bins to provide visual separation and to display averages as a diamond inside the box.
If your site has Visual Statistics and you have permissions for the /SASVisualAnalytics_capabilities/buildAnalyticalModel URI, then you can explore the data from the box plot as a new model by selecting a box, right-clicking it, selecting New object from selection, and choosing a model. A model is created that uses the category as the response and all other data items as predictors or effects.

=== Bubble Change Plots 126 ===
A bubble change plot is useful for showing the relative performance between three sets of measures from one point in time to another. Two sets of measures determine the placement of the bubbles on the axis and the third set of measures determines the sizes of the bubbles. It shows the changes in values using directed line segments (or vectors) between bubbles. The vectors show both the direction and magnitude of the change between the starting point and the ending point. Depending on your data structure, you might need to create calculated data items for the starting and ending measures. By default, the axes show X and Y, so you might want to hide the axis labels and use the title to describe the axes.
Bubble change plots require six measures: two for the starting point (X start) and ending point (X end) on the horizontal axis, two for the starting point (Y start) and ending point (Y end) on the vertical axis, and two for the starting size (Size start) and ending size (Size end) of the bubbles. In addition, vector plots can contain groups. Options are available for both sets of bubbles and the vector. For the bubbles, you can change the transparency of the bubbles and specify the size range for the bubbles. For the vector, you can change the transparency of the vectors, display or hide the arrowheads (to show direction), and specify the line thickness. In addition, you can choose to abbreviate numeric values in the legend.

=== Donut Charts 142 ===
Donut charts are similar to pie charts but have a hole in the center that can display an abbreviated total. This hole makes it easier to compare relative sizes because it forces the viewer to focus on reading the lengths of the arcs rather than the proportions of the slices. A donut chart is the default style when adding a pie chart to the canvas, but you can modify options to display a pie chart instead. Like pie charts, donut charts cannot show a slice with a zero or negative response, so if your data has these values, another type of chart should be used.
Donut charts can contain groups, use lattice columns and lattice rows, display animation, and support the hidden data role. Options are available for changing the chart style (pie or donut), adding and modifying the donut hole label, the ring width, the starting point for the arcs, the direction in which the arcs are laid out (Counterclockwise or Clockwise), specifying if small values are grouped into an "Other" slice, modifying the grouping style when multiple measures or categories are assigned to the chart (Multiples or Stack), adding a measure label to the pie, and specifying what type and how data labels are displayed. For data labels, you can choose to show category labels, actual values, and percent of total values. In addition, you can specify the data label location (Auto, Callout, Inside, or Outside) and request abbreviated numeric values.
For pie charts and donut charts, avoid using the Stack grouping style, which displays the charts as a set of stacked rings. Stacked charts can be very difficult to interpret and tend to distort the data even further. In this case, a grouped bar chart or a multi-level treemap might be a better alternative.

=== Dual Axis Bar Charts 100 ===

That is, the current value for both measures does not depend on the prior value. For example, a dual axis bar chart could be used to show customer satisfaction and the number of sales representatives' customers by continent because the values for one continent are not impacted by the values for another.
NOTE: By default, a dual axis bar chart is sorted in descending order by the value of the first measure.
Dual axis bar charts can use lattice columns and rows, display animation, and support the hidden data role. Options are available for each group of bars and enable you to specify the baseline, change the transparency of the bars, add and modify data labels and segment labels, and abbreviate numeric values. === Dual Axis Bar-Line Charts 136 ===
Dual axis bar-line charts combine a bar chart and a line chart on a shared category axis. The bar chart and the line chart have separate response axes. For the bar, use an independent measure; that is, a measure whose current value does not depend on the prior value. For the line, use a dependent measure; that is, a measure whose current value does depend on the prior value. For example, a dual axis bar-line chart could be used to show temperature and rainfall by month. For this chart, the line would display temperatures because the temperature for February depends on the value from January. The bars would show rainfall because the rainfall for February does not depend on the value from January. By default, the axis for the bars starts at zero, but the axis for the line does not start at zero and will scale to a zoomed-in view.
NOTE: By default, a dual axis bar-line chart is sorted in descending order by the value of the first measure.

For the bars, you can specify the baseline, change the transparency of the bars, and add and modify data labels and segment labels. For the line, you can specify the baseline, change the transparency of the line, specify the grouping style (Overlay unfilled, Overlay filled, or Stack filled), specify the line thickness, add markers, and add and modify data labels. In addition, options are available to abbreviate numeric values and for both the left and right Y axes.

=== Histograms 121 ===
Histograms can be used to view the distribution of a single measure. A histogram consists of a series of bars where the height represents the number of observations that fit in a specific range. Histograms are ideal for gauging the overall range of a measure and for identifying values that contain a high number of observations. Histograms can also be used to determine whether a measure is normally distributed, which can be very helpful in modeling. In fact, data distribution is key to determining the appropriate transformations and the best modeling algorithm to use. In this example, the histogram for Product Quality shows that the data is skewed to the left, indicating that a log transformation might be helpful.
Histograms require a measure and a frequency value (which can be Frequency or Frequency Percent). Options are available for changing the direction of the bars, modifying the transparency, and specifying how the boundaries of the bin ranges are determined. Bin ranges can be determined by the system (which might extend the bin ranges beyond the minimum and maximum values in the data) or can be set using measure values (which places the boundaries using the actual minimum and maximum values in the data). If the bin ranges are determined using measure values, you can set a fixed bin count and specify a fixed number of bins that will be displayed in the histogram.

=== Pie Charts 248 ===
A pie chart is best used to compare a few groups (five or less) whose values vary greatly. These charts display the relative contribution of each group to the whole using a circle that is divided into multiple slices. Pie charts are popular, but be aware that it is very hard to compare the relative sizes of slices in the chart. In addition, changes over time are difficult to detect, and pie charts take up more space than any other types of charts (like bar charts and treemaps). Because of this, pie charts should be used sparingly and only in special circumstances. Specifically, you can use a pie chart to illustrate that one value makes up the majority (as seen in this pie chart), which might be difficult to detect in a bar chart.
NOTE: By default, pie charts are sorted in descending order by the contribution of the measure. If the pie chart contains a lattice, then the slices are sorted in ascending order by the category.
Pie charts can contain groups, use lattice columns and lattice rows, display animation, and support the hidden data role. Options are available for changing the chart style (pie or donut), the starting point for the slices, the direction in which the slices are laid out (Counterclockwise or Clockwise), specifying if small values are grouped into an "Other" slice, for which you can set a minimum percentage, modifying the grouping style when multiple measures or categories are assigned to the chart (Multiples or Stack), adding a measure label to the pie, and specifying what type and how data labels are displayed. For data labels, you can choose to show category labels, actual values, and percent of total values. In addition, you can specify the data label location (Auto, Callout, Inside, or Outside) and ask to abbreviate numeric values.
If your pie chart displays more than five slices, specify a minimum percentage for "Other" slice to limit the number of slices. Avoid using ranks to limit the number of pie slices. This defeats the purpose of using a pie chart to display a part-to-whole relationship. In addition, be aware that pie charts cannot show a slice with a zero or negative response, so if your data has these values, another type of chart should be used.
NOTE: The Other slice does not display data tip values. In addition, the Other slice always sums the included values, regardless of the aggregation method selected for the measure. For example, if the aggregation method selected is Count, then the Other slice displays the sum of the individual counts.
For pie charts and donut charts, avoid using the Stack grouping style, which displays the charts as a set of stacked rings. Stacked charts can be very difficult to interpret and tend to distort the data even further. In this case, a grouped bar chart or a multi-level treemap might be a better alternative.

=== Step Plots 054 ===

=== Treemaps 109 ===
Treemaps, sometimes called tile charts, can be used to display lots of information in a small amount of space. A category or hierarchy can be used to create the tiles, and measures can be added to both size and color the tiles. Typically, the size and color are used to draw attention to areas of interest (for example, top contributors). The measures should mean something when they are compared, but they should not be the same. Treemaps are a better alternative to pie charts and donut charts to show part-to-whole relationships. This is because the treemap circumvents the problem of reading angles and provides more space for labeling. In addition, treemaps can also be used to display multi-level data, like the levels of a hierarchy.
Treemaps support the hidden data role. Options are available for arranging the layout of the tiles (Flow, Standard, or Toggle), for displaying the category level, for adding and modifying data labels, and abbreviating numeric values in the legend. A space-filling algorithm is used to lay out tiles on the treemap. This means that the same treemap might appear slightly different depending on the screen size.

=== Using Dual Axis Charts 034 ===
In general, dual axis charts can be useful when you want to display two measures with the same unit of measurement and different scales (like number of orders and the number of customers)
or when you need to display two measures with different units of measurement (like total sales and efficiency rates).
When using dual axis charts, use the left Y axis to show the primary measure and the right Y axis for the secondary measure.
To make dual axis charts easier to interpret, you can color-coordinate the axes labels and tick values with the color of the bars or lines.

=== Vector Plots 108 ===
A vector plot is useful for showing the relative performance between two sets of measures from one point in time to another. It shows the changes in values by using directed line segments (or vectors). The vectors show both the direction and magnitude of the change between the starting point and the ending point. Depending on your data structure, you might need to create calculated data items for the starting and ending measures. By default, the axes show the name of the ending value, so you might want to hide the axis labels and use the title to describe the axes.
Vector plots require four measures: two for the starting point (X Origin) and ending point (X axis) for the horizontal axis and two for the starting point (Y Origin) and ending point (Y axis) of the vertical axis. In addition, vector plots can use color to display the lines, can contain groups, use lattice columns and rows, and support the hidden data role. Options are available for changing the transparency of the vectors, displaying or hiding the arrowheads (to show direction), and specifying the line thickness.

=== Waterfall Charts 143 ===
A waterfall chart, sometimes called a progressive bar chart, is useful for showing how incremental changes lead to a final value. It shows how the initial value of a measure increases or decreases for a categorical value. The first bar begins at the initial value, and each subsequent bar begins where the previous bar ends. The length and direction of the bar indicate the magnitude and type (positive or negative). Typically, waterfall charts display the cumulative effects of sequential values (like dates), but they can show the total for any categorical data item. In this example, the waterfall chart shows the change in total orders from the same month in the previous year. The final value shows the change in total orders for the current year versus the previous year.
NOTE: Waterfall charts are known by many names: progressive bar charts, flying bricks charts, Mario charts, and bridges (in finance).
Waterfall charts can use lattice columns and rows and support the hidden data role. Options are available for specifying a baseline, displaying a trend line to connect each of the bars, modifying the spacing and transparency of the bars, and adding and modifying an initial bar and final (cumulative) bar. For the initial bar, you can specify an initial value and a label and for the final (cumulative) bar, you can specify a label. In addition, options are available for specifying that the bars are colored by the direction of the change (by default, red for decreasing, and green for increasing), adding and modifying data labels, and abbreviating numeric values.
You can change the color of the initial bar, final bar, and increase and decrease bars in the Style group.

=== Word Clouds 157 ===
Word clouds, sometimes called tag clouds, can be used to visually represent text data in a cloud-like shape. A word cloud analyzes each value of a category data item as a single text string. The value of one measure can be used to size the word, and the value of another measure can be used to color the word.
Word clouds should be avoided if analytical accuracy is desired because the size and position of the word can impact the attention placed on the word.
Words that have more letters often seem larger than words that have fewer letters. In addition, words that contain large letters (like o, m, and w) generally receive more attention than words that contain smaller letters (like l, i, and f). Lastly, words whose letters contain ascenders (the part of a lowercase letter that projects above the body of the letter: b, d, or h) or descenders (the part of a lowercase letter that projects below the body of the letter: g, p, or q) receive more attention than words that do not.
In addition, words in the middle of the word cloud attract more attention than those near the borders, and in Western cultures, words in the upper left quadrant receive more attention.
Word clouds also are not desired when viewers are searching for a specific word, as it can be difficult to locate one word out of many.
To avoid text length bias, use two- or three-letter abbreviations in the word cloud rather than full names.
NOTE: For more information about the usability studies for word clouds, see https:en.wikipedia.org/wiki/Tag_cloud.
Word clouds support the hidden data role. Options are available for arranging the layout of the words (Cloud or Rows), for specifying the difference in font sizes between the largest and smallest words, for specifying the maximum number of words displayed in the word cloud, and abbreviating numeric values in the legend.
